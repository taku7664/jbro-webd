# 디자인 시스템과 토큰

디자인 시스템은 한 번의 좋은 화면을 **반복할 수 있는 기계**로 바꿉니다. 작은 프로젝트는 `DESIGN.md` 하나와 CSS 변수면 충분하고, 커지면 아래 구조로 키웁니다.

## 토큰 세 층

| 층 | 무엇 | 예 | 규칙 |
|---|---|---|---|
| 원시(global) | 존재하는 값의 목록. 의미 없음 | `--green-600: oklch(0.45 0.09 155)`, `--space-4: 1rem` | 컴포넌트가 직접 쓰지 않음 |
| 의미(alias, semantic) | 값이 맡는 역할 | `--color-action: var(--green-600)`, `--space-stack: var(--space-4)` | 의도를 말함. 테마는 이 층의 연결만 바꿈 |
| 컴포넌트 | 한 컴포넌트 안의 값 | `--button-bg: var(--color-action)` | 의미 토큰만 참조. 꼭 필요할 때만 만듦 |

- 컴포넌트에 hex·px을 직접 쓰지 않습니다(검출기 `unmodified-shadcn-tokens`처럼 기본값 그대로도 주의).
- 다크 모드·브랜드 변형은 의미 토큰의 연결만 바꿉니다. 원시값을 덮어쓰지 않습니다.
- 토큰 이름은 값이 아니라 역할로(`--text-meta`가 `--gray-500`보다 오래 갑니다).

## 토큰 종류

색, 글꼴(패밀리·크기·굵기·행간·자간), 간격, 크기(아이콘·컨트롤 높이), 반경, 테두리 두께, 그림자(단계별), 모션(길이·이징), z-index 층, 브레이크포인트.

교환이 필요하면 W3C Design Tokens(DTCG) JSON 형식(`$value`, `$type`, `$description`)으로 내보낼 수 있습니다. 대부분의 웹 프로젝트는 CSS 변수로 시작하면 됩니다.

## 컴포넌트

- 작은 부품(버튼, 입력, 배지) → 조합(검색 막대, 카드 머리) → 영역(헤더, 가격 표) → 화면. 이 순서로 만들면 같은 결정이 반복됩니다.
- **기능 패턴**(무엇을 하나: 탐색, 필터, 비교)과 **지각 패턴**(어떻게 보이나: 반경, 그림자, 글자 성격)을 구분합니다. 브랜드 개성은 지각 패턴에, 사용성은 기능 패턴에 있습니다.
- 컴포넌트는 모든 상태를 가집니다(`interaction.md`의 상태 표).
- 변형(variant)은 실제로 다른 일을 할 때만. 크기·색 조합마다 변형을 만들면 체계가 폭발합니다.

## DESIGN.md를 키우는 두 방법

1. **먼저 정하기**: 방향을 정하고 토큰을 잠근 뒤 화면을 만듭니다(`direction.md` 경로 A·C).
2. **나중에 뽑기**: 잘 나온 화면 하나에서 반복되는 값·구조를 뽑아 토큰·컴포넌트로 정리합니다(경로 D, `ops/system.md`의 extract).

## 문서화: DESIGN.md에 들어갈 것

`templates/DESIGN.md`가 뼈대입니다. 커지면 아래 절을 이 순서로 둡니다.

1. **개요**: 방향 한 문단, 근거(레퍼런스·스타일), 시그니처
2. **색**: 원시 단계, 의미 토큰, 쓰는 곳·쓰지 않는 곳, 대비 확인 결과
3. **타이포**: 역할별 패밀리·크기·굵기·행간, 한글 설정
4. **레이아웃**: 그리드, 간격 스케일, 컨테이너 폭, 브레이크포인트
5. **깊이**: 그림자 단계와 쓰는 상황
6. **모양**: 반경, 테두리, 아이콘 규칙
7. **컴포넌트**: 핵심 컴포넌트와 상태
8. **이름 붙은 규칙**: "주 행동 색은 한 화면에 한 곳", "카드 중첩 금지" 같은 이 프로젝트만의 규칙

## 운영 (팀이 커지면)

- 누가 시스템을 바꾸나(한 사람·팀·기여 모델)를 정합니다.
- 토큰·컴포넌트 변경에 버전과 폐기 예고 기간을 둡니다.
- 디자인 도구와 코드의 토큰 원본을 하나로 정합니다.
- 시스템이 막는 것이 많아지면 예외를 기록하고, 같은 예외가 세 번 나오면 시스템을 고칩니다.

## 흔한 실수

- 원시값을 컴포넌트에 직접 써서 테마 전환이 안 됨
- 다크 모드를 원시값 반전으로 만듦
- 토큰 이름에 값이 들어가서(`--blue-text`) 색을 바꾸면 이름이 거짓말이 됨
- 쓰지 않는 토큰이 쌓임 → 정기적으로 사용처를 검색해 정리
- 시스템을 화면보다 먼저 크게 만들어 실제로 필요 없는 컴포넌트를 유지
