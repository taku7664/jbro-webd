# 모션

모션은 **상태, 관계, 위계를 설명**하거나, 그 화면이 자격을 얻은 **연출 한 번**을 만들 때 씁니다. 목적 없는 애니메이션은 나중에 갚아야 할 빚입니다.

## 모드별 쓰임

- **Persuade, Experience**: 모션이 목소리가 될 수 있습니다. 섹션마다 반복되는 등장 효과보다 잘 짠 연출 하나.
- **Operate, Read**: 모션은 피드백·상태·연속성을 위해서. 일상 전환은 빠르게. 사용자를 페이지 등장 연출 동안 기다리게 하지 않습니다.

## 쓸 자리를 찾는다

현재 모션 언어, 상호작용 상태, 대상 기기, 성능 예산을 본 뒤 모션이 아래 일을 하는 곳만 고릅니다.

- 행동을 받았다고 알려 준다 (누름, 저장)
- 상태 변화나 공간 관계를 읽히게 한다 (펼침, 이동, 정렬)
- 탐색·레이아웃 변화를 이어 준다 (목록 → 상세)
- 의미 있는 순간에 시선을 이끈다
- 선택한 세계를 몸으로 보여 준다

움직일 수 있다는 이유만으로 정적인 영역을 움직이지 않습니다.

## 모션 방침

구현 전에 짧게 적습니다:

- **연출 하나**: 저작권을 걸 만한 시퀀스나 상호작용 (없을 수도 있음)
- **연속성**: 설명이 필요한 상태·레이아웃·탐색 변화
- **피드백**: 반응이 필요한 컨트롤과 결과
- **예산**: 비싼 효과와 실행 빈도

연출은 이 제품과 이 화면에서 나와야 합니다. 일반적인 fade-and-rise, hover 들림, 패럴랙스, 스크롤 등장은 방침이 아닙니다.

## 의미에 맞는 재료

transform·opacity가 기본이지만 전부는 아닙니다.

| 전하려는 것 | 재료 |
|---|---|
| 연속성·관계 | 공유 요소 전환, FLIP, View Transitions, 의도한 공간 이동 |
| 초점·깊이 | 범위를 제한한 blur·filter·backdrop·그림자 변화 |
| 드러내기·구성 | mask, clip-path, 잘라 내기 |
| 질감·에너지 | 색, 그라디언트 위치, 질감, 셰이더 (세계와 런타임이 받쳐 줄 때) |
| 상태·피드백 | 원인과 결과를 분명하게 하는 가장 작은 변화 |

기법을 쌓아 볼거리를 만들지 않습니다. 강한 재료 하나를 연출에 쓰고 나머지는 조용히.

## 시간과 이징

| 길이 | 쓰임 |
|---|---|
| 100–150ms | 즉각 피드백 (누름, 토글) |
| 150–300ms | 일상 상태 변화 (드롭다운, 탭) |
| 300–500ms | 레이아웃·오버레이·화면 전환 |
| 500–800ms | 의도한 연출 등장 하나 |

- **나갈 때가 들어올 때보다 빠르게.**
- 등장: 자연스럽게 감속하는 곡선(`cubic-bezier(0.16, 1, 0.3, 1)` 같은 ease-out 계열). 퇴장: 가속(`ease-in` 계열). 자리 바꿈·토글: ease-in-out.
- bounce·elastic 이징을 습관처럼 쓰지 않습니다. 일상 UI에서는 장난감처럼 보입니다.
- 긴 피드백은 지연처럼 느껴집니다.
- 목록이 목록으로 나타날 때만 순차 지연(stagger) 30–80ms. 전체 지연에 상한을 두고, 스크롤로 들어오는 모든 섹션을 순차 목록처럼 다루지 않습니다.

## 구현

- 선언적 상태와 짧은 시퀀스: CSS transition·keyframes
- 중단·순서·동적 값: Web Animations API 또는 프로젝트에 이미 있는 모션 라이브러리
- 상태 사이 연속성: View Transitions, 공유 요소
- 스크롤 연동: 스크롤 관계 자체가 의미일 때만, `scroll-timeline` 또는 IntersectionObserver. scroll 이벤트 리스너로 매 프레임 계산하지 않습니다.
- 이미 있는 스택으로 깔끔하게 되는 효과에 의존성을 추가하지 않습니다.

## 반드시 지킬 것

- **기본 상태는 보이는 상태입니다.** 스크립트·애니메이션이 실패하거나 늦어도 내용이 보여야 합니다. `opacity: 0`, `clip-path: inset(0 0 100% 0)`에서 시작하는 진입은 뒤쪽 탭·느린 기기·캡처 도구에서 화면을 비웁니다(시험에서 실제로 발생, 검출기 `hidden-entrance`).
- 레이아웃을 바꾸는 속성(`width`, `height`, `top`, `left`, `margin`, `padding`)을 습관적으로 애니메이션하지 않습니다. 펼침·접힘은 `grid-template-rows: 0fr → 1fr`, 위치·크기는 transform.
- blur·filter·그림자·캔버스·셰이더는 영역을 제한합니다. `will-change`는 애니메이션 직전에만.
- transform이라서 빠르다고 가정하지 않고 대상 기기에서 잽니다.

## 접근성

- 모든 웹 애니메이션에 `prefers-reduced-motion` 경로를 둡니다. **움직임은 줄이되 의미 있는 피드백은 남깁니다.** 색·불투명도 변화로 상태를 알리는 것은 남겨도 됩니다. 전부 끄는 것이 목표가 아닙니다.
- 자동 재생·소리 설정을 존중합니다. 필수가 아닌 반복 애니메이션은 화면 밖이나 숨겨진 탭에서 멈춥니다.
- 5초 넘게 자동으로 움직이는 것에는 멈춤 수단을 둡니다.
- 초당 3회 넘게 번쩍이는 효과는 쓰지 않습니다.

## 로딩

- 내용 모양을 아는 곳: 스켈레톤
- 되돌릴 수 있는 가벼운 행동: 낙관적 UI(먼저 반영하고 실패하면 되돌림)
- 걸리는 시간을 아는 긴 작업: 진행률
- 짧고 모양을 모르는 대기: 작은 스피너. 0.3초 안에 끝나면 아예 보이지 않게 지연 표시

## 확인

- 연출이 이 세계와 이 화면에만 있는 것인가?
- 보조 애니메이션이 모두 피드백·상태·관계를 설명하는가? 빼면 의미가 사라지는가, 장식만 사라지는가?
- 중간에 끊거나 반복해도 제대로 동작하는가?
- reduced-motion에서 움직임은 줄고 피드백은 남는가?
- 애니메이션이 멈춘 상태로 캡처해도 내용이 보이는가?
- 비싼 효과가 대상 기기에서 부드러운가?
