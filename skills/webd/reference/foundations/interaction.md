# 상호작용과 상태

사람이 화면을 만지는 순간마다 화면은 답해야 합니다: 이걸 누를 수 있나(어포던스), 눌렀나(피드백), 무슨 일이 일어났나(결과), 되돌릴 수 있나(안전). 정적인 시안에서는 보이지 않는 이 부분이 실제 제품 품질의 절반입니다.

## 컴포넌트마다 그리는 상태

| 상태 | 무엇을 보여 주나 |
|---|---|
| 기본 | 누를 수 있다는 것 |
| hover | 포인터가 올라갔다 (터치 기기에는 없음 → hover에만 정보를 두지 않음) |
| focus-visible | 키보드 포커스가 여기 있다 |
| active (눌림) | 지금 누르고 있다 |
| 선택·켜짐 | 현재 고른 것 |
| 비활성 | 지금은 못 쓴다, 가능하면 **왜** 못 쓰는지 |
| 로딩 | 처리 중, 두 번 누르지 않게 |
| 성공 | 끝났다, 다음에 무엇을 할지 |
| 오류 | 무엇이 잘못됐고 어떻게 고치는지 |
| 빈 상태 | 아직 없다, 왜, 어떻게 시작하는지 |

새 컴포넌트를 만들 때 이 표를 채운 뒤 끝냅니다.

## 버튼 위계

- 한 영역에 **주 행동은 하나**. 채운 버튼.
- 대안 행동은 보조(테두리 또는 옅은 면), 덜 중요한 것은 글자 버튼.
- 파괴적 행동(삭제, 해지)은 따로 구별되는 모양·색. 주 행동 자리에 두지 않습니다.
- 모든 버튼이 같은 모양이면 무엇이 중요한지 알 수 없습니다.
- 버튼 글자는 동작을 말합니다: "확인" 대신 "주문하기", "삭제" 대신 "프로젝트 삭제"(`ux-writing.md`).

## 포커스

- `:focus-visible`에 2px 이상, 주변과 대비 3:1 이상의 표시. `outline-offset`으로 요소와 살짝 띄웁니다.
- `outline: none`만 쓰고 대체가 없으면 키보드 사용자는 길을 잃습니다(검출기 `focus-removed`, 렌더 검사 `focus-indicator`).
- Tab 순서가 화면 읽기 순서와 같아야 합니다.
- 모달·드로어: 열리면 안으로 포커스를 옮기고, 안에 가두고(뒤쪽은 `inert`), 닫히면 연 버튼으로 돌려줍니다. Esc로 닫힙니다.

## 폼

- 모든 입력에 **보이는 라벨**. placeholder는 형식 예시(`예: 010-1234-5678`)로만. 입력하면 사라지는 placeholder를 라벨로 쓰지 않습니다.
- 도움말은 입력 아래에, `aria-describedby`로 연결.
- 검증 시점: 입력을 마치고 나갈 때(blur). 이미 오류가 보인 칸은 고치는 동안 다시 검사해 오류가 바로 사라지게.
- 오류는 **그 칸 바로 옆에**, 무엇이 틀렸고 어떻게 고치는지. 제출 시 오류가 여럿이면 위에 요약 + 각 칸으로 가는 링크, 첫 오류 칸으로 포커스.
- 필수·선택 표시는 적은 쪽에만 붙입니다(대부분 필수면 "선택"만 표시).
- 알맞은 입력 종류와 자동 완성: `type="email"`, `inputmode="numeric"`, `autocomplete="postal-code"`.
- 제출 중에는 버튼을 로딩 상태로, 중복 제출 방지.
- 입력한 내용은 오류가 나도 지우지 않습니다.

## 파괴적 행동

| 되돌릴 수 있나 | 방법 |
|---|---|
| 되돌릴 수 있음 | 바로 실행 + "실행 취소" 토스트 (몇 초) |
| 되돌릴 수 없음, 영향 작음 | 확인 대화상자. 버튼에 대상 이름("'디자인 시안' 삭제") |
| 되돌릴 수 없음, 영향 큼 | 대상 이름을 직접 입력해 확인 |

확인 대화상자를 모든 행동에 붙이면 사람들은 읽지 않고 누릅니다.

## 피드백 시간

- 0.1초 안: 즉시 반응한 것처럼 느낌. 누름 피드백은 이 안에.
- 1초 안: 흐름이 끊기지 않음. 넘으면 로딩 표시.
- 10초 넘음: 진행률과 취소 수단, 가능하면 백그라운드 처리.

## 대화상자·드로어·하단 시트

| 상황 | 선택 |
|---|---|
| 지금 결정해야 다음으로 갈 수 있음, 짧은 내용 | 모달 대화상자 |
| 현재 화면을 보면서 편집·상세 확인 | 드로어(옆) |
| 모바일에서 짧은 선택·행동 목록 | 하단 시트 |
| 끼어들 필요 없는 알림 | 토스트·인라인 메시지 |
| 긴 작업, 공유할 주소가 필요 | 별도 페이지 |

방해도 보호도 필요 없는 작업에 모달을 쓰지 않습니다(`ai-tells.md`).

## 터치

- 터치 대상 44×44px 이상, 대상 사이 8px 이상. 보이는 표시가 작아도 누르는 영역은 넓게.
- hover로만 드러나는 기능은 터치에서 사라집니다. 항상 보이게 하거나 다른 진입점.
- 길게 누르기·스와이프는 숨은 동작입니다. 같은 일을 하는 보이는 수단도 둡니다.

## 확인

- 각 컴포넌트에 위 상태 표가 다 있는가? (특히 로딩·오류·빈 상태)
- 키보드만으로 모든 행동을 할 수 있고, 포커스가 늘 보이는가?
- 폼 오류가 칸 옆에 무엇을·어떻게로 나오는가?
- 파괴적 행동의 안전장치가 위험도에 맞는가?
- 터치 기기에서 hover 전용 정보가 없는가?
