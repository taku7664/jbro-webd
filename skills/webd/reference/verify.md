# 검증

검증은 세 겹입니다. 앞 단계가 못 잡는 것을 뒤 단계가 잡습니다.

## 1. 자동 검사

> 초안 단계: WebD 전용 검출기(`scripts/`)는 아직 없습니다. 아래 중 쓸 수 있는 것을 씁니다.

- 프로젝트에 Impeccable이 설치돼 있으면 `npx impeccable detect <경로 또는 URL>`을 실행할 수 있습니다. 설치·다운로드가 필요하면 사용자 승인을 먼저 받습니다.
- 없으면 소스에서 직접 찾습니다: `background-clip: text`(그라디언트 텍스트), `backdrop-filter`(글래스), `border-left: [2-9]px`(강조 바), 보라 계열 hex, 금지 폰트 이름, 중첩된 카드 클래스.
- 결과는 `ai-tells.md` 항목과 대응시켜 정리합니다. 자동 검사가 0건이어도 "AI 티 없음"이라고 단정하지 않습니다.

## 2. 렌더 확인

브라우저·스크린샷 도구가 있으면 실제 화면을 봅니다.

- 해상도: 375px, 768px, 1440px. 가능하면 1024px도
- 라이트·다크 모드(지원하는 경우)
- 키보드 Tab으로 포커스 이동
- 확인한 것과 확인하지 못한 것을 나눠 기록합니다.

한 번 볼 때 여러 문제를 함께 찾고, 몰아서 고친 뒤 다시 봅니다. 수정 하나마다 스크린샷을 찍지 않습니다.

## 3. 비평

렌더를 보고 디자이너 입장에서 평가합니다. 자기 결과물이라고 너그럽게 보지 않습니다.

- **첫인상**: 3초 안에 무엇을 하는 화면인지 보이는가. 시선이 처음 가는 곳이 의도한 곳인가.
- **브리프 대조**: `PRODUCT.md`의 목표와 `DESIGN.md`의 금지 조건을 지켰는가. 요구사항이 화면에서 바로 찾아지는가.
- **시그니처**: 이 프로젝트에서만 나올 결정이 실제로 보이는가. 같은 브리프로 다른 모델이 만들어도 똑같이 나올 화면인가.
- **하한선**: `craft-floor.md` 위반
- **AI 티**: `ai-tells.md` 대조. 근거 없는 항목만 올립니다.
- **덜어낼 것**: 빼도 나빠지지 않는 요소 하나

## 지적을 수정 스펙으로

지적은 "더 세련되게" 같은 말로 남기지 않고 바로 실행할 수 있는 스펙으로 바꿉니다.

```
- 위치: 가격 섹션 카드 3개
- 문제: 같은 크기 카드 반복, 추천 플랜이 구분되지 않음
- 수정: 추천 플랜만 1.2배 너비 + primary 테두리 2px, 나머지 그림자 제거
- 근거: ai-tells.md 페이지 뼈대 1번, DESIGN.md 금지 조건 2번
```

수정 범위가 크면 이 스펙 목록을 서브에이전트에 나눠 줄 수 있습니다. 같은 파일을 두 작업이 동시에 고치지 않게 나눕니다.
