# 화면 구조 판단

화면 요구사항은 화면 이름("편집기", "관리자", "설정")에서 나오지 않고, **그 화면이 하는 일**에서 나옵니다. 아래 일곱 질문에 답하면 처음 보는 화면이라도 필요한 영역·동작·상태가 정해집니다. `surfaces/` 문서는 이 질문에 미리 답해 둔 예시일 뿐이며, 목록에 없다고 기준이 없는 것이 아닙니다.

모드(`modes.md`)가 "얼마나 과감하게"를 정한다면, 구조는 "무엇이 어디에 있어야 하는가"를 정합니다. 둘 다 정한 뒤 방향 단계로 넘어갑니다.

## 일곱 질문

답은 짧은 낱말로 고르고, 모르면 사용자에게 묻거나 `미정`으로 둡니다. 화면이 여러 개면 화면마다 답합니다.

| # | 질문 | 고를 답 |
|---|---|---|
| 1 | **대상**: 사용자가 이 화면에서 만들거나 고치는 것이 있는가? | 없음 / 하나 / 여러 개(목록) |
| 2 | **저장**: 그 대상의 변경은 언제 확정되는가? | 없음 / 즉시 반영 / 명시 저장 / 제출·승인 |
| 3 | **입력과 결과**: 입력이 결과물을 만드는가, 언제 보이는가? | 없음 / 실시간 / 요청 시 생성 / 오래 걸리는 작업 |
| 4 | **순서**: 입력에 정해진 순서가 있는가? | 자유 / 권장 순서 / 강제 단계 |
| 5 | **빈도**: 같은 사람이 얼마나 자주, 오래 쓰는가? | 처음 한 번 / 가끔 / 매일 여러 번·오래 |
| 6 | **손실**: 잘못되면 무엇을 잃는가? | 없음 / 입력한 내용 / 생성 결과·비용 / 되돌릴 수 없는 외부 반영 |
| 7 | **동시에 볼 것**: 판단하려면 무엇을 나란히 봐야 하는가? | 하나 / 둘(입력+결과, 원본+사본, 목록+상세) / 셋 이상 |

## 답에서 나오는 것

각 답은 "꼭 넣을 것"과 "하지 말 것"을 끌고 옵니다. 여러 답이 겹치면 모두 적용합니다.

| 답 | 꼭 넣을 것 | 하지 말 것 |
|---|---|---|
| 대상 없음 | 모드의 첫 화면 규칙(`modes.md`) | 작업 막대·저장 버튼을 장식으로 |
| 대상 하나 | 대상의 이름과 정체(이름 칸, 출처·버전)가 첫 화면 맨 위 | 대상 이름 자리에 화면 소개 제목 |
| 대상 여러 개 | 목록 + 선택한 항목 상세, 검색·정렬·필터, 선택 상태 표시 | 상세로 갈 때마다 목록을 잃는 이동 |
| 즉시 반영 | 반영됨 표시(짧은 확인), 되돌리기 | "저장" 버튼을 따로 두어 두 방식을 섞기 |
| 명시 저장 | 저장 상태 문구(변경 없음 / 저장하지 않은 변경 / 저장 중 / 저장 실패와 이유), 저장·사본 저장·되돌리기, `Ctrl+S`, 나가기 전 경고 | 저장 버튼을 스크롤 아래에, 상태를 색으로만 |
| 제출·승인 | 제출 전 확인(무엇이 어디로 가는지), 제출 뒤 상태 추적, 제출 후 수정 가능 여부 명시 | 확인 없이 바로 제출 |
| 실시간 결과 | 결과 영역을 입력 옆에 고정, 갱신 시점(입력 즉시 / 잠깐 멈춘 뒤) 결정 | 결과를 보려고 스크롤·탭 전환 |
| 요청 시 생성 | 실행 버튼, 실행 전 조건 요약, 진행 표시, 결과와 그 결과를 만든 입력의 짝 | 입력이 바뀌었는데 이전 결과를 최신처럼 보여 주기("입력 바뀜" 표시) |
| 오래 걸리는 작업 | 진행·남은 시간·취소, 다른 화면으로 가도 이어지는 상태 표시, 끝나면 알림 | 화면 전체를 막는 로딩 |
| 권장 순서 | 영역에 번호, 한 화면에 함께 두기, 어느 단계부터 고쳐도 됨 | 강제 마법사로 막기 |
| 강제 단계 | 단계 표시(현재·전체), 이전으로 돌아가도 값 유지, 단계별 검증 | 마지막에야 앞 단계 오류 알리기 |
| 처음 한 번 | 설명 문구, 넉넉한 여백, 기본값 제안 | 숙련자용 밀도·단축키만으로 설계 |
| 매일 여러 번·오래 | 밀도, 단축키와 표시, 마지막 상태 기억(열린 패널·정렬·스크롤), 차분한 색 | 소개 문구·큰 여백·장식 모션·매번 뜨는 안내 |
| 입력 손실 | 자동 임시 저장 또는 나가기 경고, 되돌리기 | 실수 한 번에 입력이 사라지는 초기화 |
| 생성 결과·비용 | 실행 전 비용·제한 표시(문자 수, 횟수), 결과 보관, 조건을 몰래 자르거나 바꾸지 않기 | 제한 초과를 실행 뒤에 알리기 |
| 되돌릴 수 없는 반영 | 대상·범위를 이름으로 확인하는 단계, 위험 버튼을 주 버튼과 떨어뜨리기 | "정말 하시겠습니까?"만 있는 확인 |
| 둘을 나란히 | 2단, 각 영역 독립 스크롤, 나눔 비율 조절, 좁은 폭에서는 탭으로 전환 | 한 칼럼에 세로로 쌓아 비교 불가 |
| 셋 이상 | 접을 수 있는 패널, 주 영역 하나를 정하고 나머지는 보조 | 같은 무게의 패널 셋 |

## 구조 유형

답을 묶으면 몇 가지 유형이 나옵니다. 이름은 설명용이며, 유형에 끼워 맞추지 말고 위 표의 답을 우선합니다.

| 유형 | 대표 답 | 예시 문서 |
|---|---|---|
| 페이지형 | 대상 없음 | `surfaces/landing.md`, `pricing.md`, `docs.md`, `portfolio.md` |
| 감시형 | 대상 없음(읽기만), 매일, 셋 이상 | `surfaces/dashboard.md` |
| 입력형 | 대상 하나, 제출, 처음 한 번 | `surfaces/forms.md` |
| 목록·상세형 | 대상 여러 개, 즉시 반영 또는 명시 저장 | `surfaces/dashboard.md` 표 절 |
| 작업대형 | 대상 하나, 명시 저장, 실시간 또는 요청 시 생성, 매일, 둘을 나란히 | 아래 골격 |
| 단계형 | 강제 단계 | `surfaces/forms.md` 결제 절 |

상태 화면(빈·오류·로딩)은 유형과 상관없이 붙습니다: `surfaces/states.md`.

## 작업대형 골격

편집기, 조합기, 생성 도구, 설정 편집기처럼 "대상 하나를 오래 만지며 결과를 보는" 화면의 기본 배치입니다. 문서 편집기(본문이 대상)와 설정형 편집기(칸 묶음이 대상) 모두 같은 골격에서 시작해 주 영역만 바꿉니다.

1. **작업 막대** (맨 위, 스크롤해도 보이게): 대상 이름(고칠 수 있는 칸), 저장 상태 문구, 새로 만들기·열기·저장·사본 저장·되돌리기. 출처(어디서 복제했는지, 버전)가 있으면 그 아래 한 줄.
2. **입력 영역**: 권장 순서가 있으면 번호 붙은 묶음, 없으면 의미로 묶은 접을 수 있는 구역. 긴 글 입력칸은 크기 조절과 글자 수.
3. **결과·검사 영역**: 입력이 만든 결과(미리보기, 조합된 글, 렌더), 제한 표시(글자 수·바이트·비용), 실행 전 막는 조건과 그 이유. 입력 영역과 독립 스크롤.
4. **보조 패널**(필요할 때만): 자료 목록, 기록, 속성. 접을 수 있게.

규칙:
- 첫 화면(1280×800)에 작업 막대, 입력의 시작, 결과 영역이 함께 보입니다.
- 화면 소개 제목·설명 문단 대신 대상 이름이 가장 눈에 띕니다. 화면 이름은 탭·내비게이션의 현재 표시로 충분합니다.
- 패널 사이 구분은 선이나 면 한 가지로. 패널마다 그림자·카드를 겹치지 않습니다.
- 주 동작 색은 저장·실행에만. 나머지 도구 모음 버튼은 같은 모양의 보조 버튼.
- 좁은 폭에서는 입력·결과를 탭으로 바꾸고, 결과 탭 이름에 막힌 항목 수를 붙입니다("미리보기·확인 · 막힘 2"). 작업 막대의 덜 쓰는 동작은 "더 보기" 메뉴로 **접습니다. 숨겨서 없애지 않습니다.** 목록이 있으면 좁은 폭에서도 목록을 여는 버튼을 남깁니다. 단축키 표시(`Ctrl+S`)는 좁은 폭에서 뺍니다.
- 주제 세계는 결과 영역에서 가장 크게, 입력 영역에서는 단위·용어 정도로 드러냅니다(`modes.md`「Operate에서 주제 세계 드러내기」). 골격만 맞추고 세계가 없으면 아무 분야에나 붙는 관리 화면이 됩니다.
- 결과 영역이 길어 제출·실행 버튼이 아래로 밀리면 그 버튼을 패널 아래에 고정(`position: sticky; bottom: 0`)해 스크롤 없이 보이게 합니다. 저장은 작업 막대, 제출은 결과 영역 아래가 기본 자리입니다.
- 저장 상태가 "저장 중"이면 제출·실행도 막습니다. 저장이 끝난 내용만 내보냅니다.
- 패널 안 `position: absolute` 요소가 문서를 늘리지 않게 스크롤 패널에 `position: relative`를 줍니다(`craft-floor.md`).

## 방향 단계로 넘길 때

딜러에 모드와 구조 유형을 넘깁니다: `dealer.mjs --mode operate --structure workbench`. 유형이 둘 겹치면(목록·상세 + 작업대형처럼) 쉼표로 함께 넘깁니다: `--structure list-detail,workbench` (두 유형에 공통인 구성 방식만 나옴). 유형 이름: page(페이지형), monitor(감시형), input(입력형), list-detail(목록·상세형), workbench(작업대형), steps(단계형). 넘기지 않으면 도구 화면에도 포스터식 패가 나옵니다.

## 페이지형 쏠림 점검

대상이 있는 화면(1번 답이 "하나" 또는 "여러 개")에서 아래가 보이면, 모델 기본값인 홈페이지 구성으로 끌려간 것입니다. 하나라도 있으면 고칩니다.

- 맨 위에 큰 제목과 소개 문장이 있고, 대상 이름은 그보다 작다
- 기능을 소개하는 카드 줄(아이콘 + 제목 + 설명)
- 가운데 정렬된 좁은 칼럼과 넓은 위아래 여백
- 첫 화면에 작업 대상이나 입력이 보이지 않는다
- 저장·실행 버튼을 찾으려면 스크롤해야 한다
- "시작하기", "지금 체험" 같은 유도 문구
- 작업 면 뒤의 장식 그라디언트·큰 일러스트·배경 모션
- 섹션마다 다른 배경색 띠로 페이지를 나눈다

## 기록

답을 `PRODUCT.md`의 「화면」 표 「구조」 칸에 한 줄로 적습니다.

```
장면 조합 | Operate | 대상 1 · 명시 저장 · 실시간 결과 · 권장 순서 · 매일 · 생성 비용 · 입력+결과 → 작업대형
```
