# 품질 하한선

UI 코드를 고치기 직전에 읽습니다. 계획만 세우는 단계에서는 읽지 않습니다. 체크리스트를 사용자에게 낭독하지 말고 결과물로 지킵니다.

`DESIGN.md`나 사용자가 고정한 값이 이 문서와 다르면 그쪽을 따릅니다. 단, **[필수]** 표시 항목은 예외 없이 지킵니다.

## 접근성 [필수]

- 본문·placeholder 대비 4.5:1 이상, 큰 글자(24px 이상 또는 18.66px 굵게) 3:1 이상
- 키보드 포커스가 보입니다. `outline: none`만 쓰고 대체 스타일이 없으면 안 됩니다.
- `prefers-reduced-motion`을 존중합니다.
- 아이콘만 있는 버튼에는 접근 가능한 이름이 있습니다.
- 확대(`user-scalable=no`, `maximum-scale=1`)를 막지 않습니다.
- 색만으로 의미를 전달하지 않습니다.
- 터치 대상은 최소 44×44px

## 타이포

- 본문 16px 이상, 행간 1.5 안팎. 한글 본문은 1.6–1.8도 검토
- 본문 줄 길이 65–75ch 이내(한글은 더 짧게)
- 제목에 `text-wrap: balance`, 본문에 `text-wrap: pretty` 검토
- 디스플레이 자간은 과하게 좁히지 않습니다(-0.04em 정도가 한계)
- 실제 카피를 모든 해상도에 넣어 넘치는 곳을 고칩니다.

## 색

- 색 배경 위의 보조 텍스트는 회색 대신 그 배경 색조나 본문 색을 섞어 씁니다.
- 그림자는 오프셋과 부드러운 블러가 있어야 깊이로 읽힙니다. 오프셋 없는 색 번짐은 장식입니다.
- 브라우저 기본값이 남는 곳도 디자인입니다: 텍스트 선택 색, 캐럿, 스크롤바, 포커스 링, 밑줄 오프셋, 표 숫자.

## 레이아웃

- 관련 요소는 가깝게, 그룹 사이는 넓게. 간격 값이 하나뿐이면 리듬이 없습니다.
- 카드 안에 카드를 넣지 않습니다.
- 텍스트가 뷰포트 가장자리에 붙지 않습니다. 모바일 좌우 여백 16px 이상
- 가로 스크롤이 생기지 않습니다.
- 제목 단계를 건너뛰지 않습니다(h1 → h3).

## 상태

hover, focus, active, disabled, loading, empty, error 상태를 모두 만듭니다. 버튼 문구는 동작을 말하고, 오류 문구는 문제와 해결 방법을 말합니다.

## 모션

- 사용자 행동 없이 움직이는 연출은 한 번만(페이지 진입 또는 한 번의 공개)
- 모든 섹션에 같은 fade-up을 붙이지 않습니다.
- 기본 상태는 보이는 상태입니다. 애니메이션이 실패해도 내용이 `opacity: 0`으로 남으면 안 됩니다.
- 일상적인 UI(대화상자, 드롭다운)에 bounce·elastic 이징을 쓰지 않습니다.
- `transform`, `opacity` 위주로 애니메이션합니다.

## 아이콘·이미지

- 아이콘은 한 라이브러리 또는 직접 그린 SVG로, 선 두께와 크기를 통일합니다. 이모지·유니코드 기호로 아이콘을 대신하지 않습니다.
- 이미지에는 의미 있는 `alt`, 장식이면 `alt=""`
- 이미지를 거의 불투명한 오버레이 밑에 묻지 않습니다.
