# 맥락 잡기

디자인 결정의 근거가 될 정보를 모아 `PRODUCT.md`에 남깁니다. 이후 단계는 이 파일을 읽고 시작합니다.

## 순서

1. 프로젝트 루트에 `PRODUCT.md`·`DESIGN.md`가 있는지 확인합니다. 있으면 읽고, 빈 칸만 채웁니다.
2. 기존 코드가 있으면 스택(`package.json` 의존성 등)과 현재 쓰는 폰트·색·컴포넌트 라이브러리를 확인합니다. 스택은 추측하지 않습니다.
3. 아래 질문 중 **답이 없으면 결과가 달라지는 것만** 묻습니다. 한 번에 3개 이하로 묻고, 사용자가 이미 말한 것은 다시 묻지 않습니다.
4. `<스킬 폴더>/templates/PRODUCT.md`를 복사해 채웁니다. 모르는 칸은 `미정`으로 두고 지어내지 않습니다.

## 질문 목록

- **무엇**: 제품·주제가 무엇인가. 실제 콘텐츠(이름, 기능, 카피)가 있는가.
- **누구**: 누가, 어떤 상황에서 보는가. (출퇴근길 휴대폰, 업무용 큰 모니터 등)
- **목표**: 이 화면에서 방문자가 무엇을 하면 성공인가 → 모드 결정 (`modes.md`)
- **취향 신호**: 좋아하는 사이트·브랜드·물건, 절대 쓰기 싫은 색·폰트·느낌
- **고정 사항**: 이미 정해진 브랜드 색, 로고, 폰트, 스타일 이름, 레퍼런스 이미지
- **제약**: 스택, 컴포넌트 라이브러리, 다크 모드 필요 여부, 지원 언어(한글 포함 여부), 성능 예산

## 주제에서 출발하기

독특함은 대부분 주제의 세계에서 나옵니다. 주제와 관련된 재료·도구·인쇄물·간판·용어를 3–5개 적어 두면 방향 단계에서 레퍼런스 후보가 됩니다. 예: 커피 원두 구독 → 원두 포대 스텐실, 로스팅 곡선 그래프, 카페 메뉴판 손글씨.

## 취향 신호 다루기

사용자가 말한 취향은 제안이 아니라 **고정(pin)** 으로 기록합니다. 방향 단계에서 이 축은 건드리지 않고 나머지 축만 정합니다.
