# onboard — 첫 실행과 빈 상태

새 사용자가 **첫 유용한 결과**에 닿게 돕는 작업입니다. 기능 설명 투어가 아니라, 가치를 경험하기까지의 거리를 줄이는 일입니다.

## 원칙

- **말하지 말고 보여 준다.** 기능 설명 화면 다섯 장보다, 바로 해 볼 수 있는 첫 행동 하나.
- **가능하면 건너뛸 수 있게.** 숙련자는 안내를 싫어합니다(`ops/critique.md` 숙련자 페르소나).
- **가치까지의 시간**을 잽니다. 가입부터 첫 결과까지 몇 단계·몇 초인가? 그중 지금 꼭 필요하지 않은 단계(프로필 완성, 팀 초대, 알림 설정)를 뒤로 미룹니다.
- **의식보다 맥락.** 처음에 모든 걸 가르치지 말고, 기능이 필요한 순간에 그 자리에서.
- **사용자를 존중.** 과장된 환영 문구, 축하 폭죽 남발, 아이 다루듯 하는 말투를 피합니다.

## 첫 실행 설계

1. **첫 화면에서 할 수 있는 한 가지**를 정합니다. 예: 메모 앱이면 바로 쓰기, 분석 도구면 예시 데이터로 첫 차트.
2. **빈 화면을 예시로 채우는 선택지**: 예시 데이터·템플릿으로 시작하게 하되, 예시라는 표시와 한 번에 지우는 방법.
3. **진행 체크리스트**는 단계가 정말 여럿이고 순서가 의미 있을 때만. 3–5개, 각 항목이 실제 가치로 이어지게. 다 하면 사라지게.
4. **가입 전에 써 보게** 할 수 있으면 그렇게. 가입은 저장·공유가 필요한 순간에.

## 기능 발견

- 새 기능은 처음 마주치는 자리에 한 번, 짧게(코치 마크·인라인 배지). 닫으면 다시 안 뜨게.
- 연속 툴팁 투어(1/7, 2/7 …)는 대부분 건너뛰어집니다. 꼭 필요하면 3단계 이하, 언제든 종료.
- 키보드 단축키는 메뉴 옆에 표시해 자연스럽게 익히게.

## 빈 상태

빈 상태는 첫인상이자 막다른 길이 되기 쉬운 곳입니다. 종류마다 다르게 씁니다(`ux-writing.md`).

| 종류 | 담을 것 |
|---|---|
| 처음 사용 | 여기에 무엇이 쌓이는지 + 왜 좋은지 + 시작 버튼 (+ 채워졌을 때 모습의 작은 미리보기) |
| 다 처리함 | 끝냈다는 인정 + 다음 행동 |
| 검색·필터 결과 없음 | 무엇을 찾았는지 + 필터 해제·철자 확인·전체 보기 |
| 권한 없음 | 왜 + 누구에게 요청 |
| 불러오기 실패 | 무엇이 있어야 하는지 + 다시 시도 |

- 빈 상태 그림은 선택입니다. 넣는다면 제품 세계에 맞게, 흔한 무료 일러스트 스타일(둥근 사람, 파란 식물)은 피합니다. 그림 없이 잘 쓴 문장과 버튼이 더 낫습니다.
- 빈 상태의 버튼은 그 화면의 주 행동과 같은 스타일.

## 도움말

- 결정 지점 옆 짧은 설명(`ⓘ` 툴팁 또는 인라인 문장). 툴팁 안에 필수 정보를 숨기지 않습니다.
- 검색되는 도움말 문서로 가는 길을 일관된 위치에.

## 측정

- 가입 → 첫 핵심 행동까지 걸린 시간·단계
- 첫 주 재방문
- 안내 건너뛰기 비율 (높으면 안내가 필요 없거나 방해된다는 신호)

## 확인

- 첫 화면 5초 안에 첫 행동이 보이는가?
- 안내를 건너뛰어도 주 작업을 할 수 있는가?
- 모든 빈 상태에 다음 행동이 있는가?
- 예시 데이터를 쉽게 지울 수 있는가?
