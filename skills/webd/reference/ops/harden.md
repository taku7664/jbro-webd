# harden — 실제 데이터·실패·극단에서 버티게

시안은 이상적인 데이터로 만들어집니다. 실제 제품은 긴 이름, 빈 목록, 끊긴 네트워크, 권한 없는 사용자, 다른 언어를 만납니다. harden은 화면이 그런 조건에서도 **쓸 수 있게** 만드는 작업입니다.

## 먼저 무엇이 위험한지 본다

대상 화면의 데이터·입력·외부 호출·사용자 유형을 나열하고, 아래 영역 중 해당하는 것만 다룹니다.

## 글자 넘침과 줄바꿈

- 실제 최댓값으로 시험합니다: 30자 이름, 200자 제목, 6자리 금액, 긴 이메일·URL.
- 한 줄이어야 하는 곳(버튼, 탭, 표 칸)은 `text-overflow: ellipsis` + 전체 내용을 볼 방법(툴팁, `title`, 펼치기).
- 여러 줄 허용하는 곳은 `-webkit-line-clamp`로 줄 수 제한.
- flex·grid 자식이 내용 때문에 넘치면 `min-width: 0`.
- 한글은 `word-break: keep-all` + `overflow-wrap: anywhere`(`hangul.md`). 긴 영단어·URL이 칸을 뚫지 않게.
- 숫자가 커질 때 표 칸이 흔들리지 않게 `tabular-nums`, 오른쪽 정렬.

## 다국어 (i18n)

- 번역으로 30–40% 늘어나도 버티게. 고정 폭 버튼 금지.
- 날짜·숫자·통화는 `Intl.DateTimeFormat`, `Intl.NumberFormat`으로 지역 형식.
- 복수형·조사(을/를, 이/가)를 문자열 조합으로 만들지 않습니다. 메시지 단위로 번역하거나 조사가 필요 없는 문장으로.
- 오른쪽에서 왼쪽 언어를 지원하면 `margin-left` 대신 논리 속성(`margin-inline-start`), 방향 아이콘 뒤집기.
- 이미지 안에 글자를 넣지 않습니다.

## 오류 처리

- 네트워크 실패, 서버 오류(5xx), 인증 만료(401), 권한 없음(403), 없음(404), 요청 제한(429), 시간 초과를 각각 어떻게 보여 줄지 정합니다.
- 메시지는 무엇이·어떻게(`ux-writing.md`). 데이터가 안전한지 말합니다.
- 다시 시도 버튼. 자동 재시도는 간격을 늘려 가며 횟수 제한.
- 입력 중이던 내용을 오류로 잃지 않게. 로컬에 임시 저장.
- 화면 일부 실패가 전체를 깨지 않게 영역별 오류 경계.
- 오프라인 상태를 알리고, 가능하면 읽기는 계속되게.

## 경계 상황

- **0개**: 빈 상태(`ux-writing.md`, `ops/onboard.md`)
- **1개**: 복수형 문구, 단일 항목 레이아웃이 어색하지 않은지
- **아주 많음**: 1,000개 목록은 페이지네이션·가상 스크롤, 숫자는 "999+"
- **없는 값**: 프로필 사진 없음(이니셜 대체), 설명 없음, 가격 미정
- **동시성**: 두 번 클릭, 다른 탭에서 바꿈, 오래된 데이터 위에 저장
- **시간**: 시간대, 자정 넘김, 오래된 날짜("3년 전"), 미래 날짜
- **권한별**: 보기만 가능한 사용자에게 편집 버튼을 숨길지 비활성+이유를 보여 줄지 정함

## 입력 검증

- 받을 때 너그럽게: 전화번호의 하이픈·공백, 카드 번호 공백, 앞뒤 공백 허용 후 정규화.
- 클라이언트 검증은 편의, 서버 검증이 진짜. 둘의 메시지를 맞춥니다.
- 길이 제한은 입력 중에 남은 글자 수로 보여 줍니다(`120/200`).
- 붙여넣기를 막지 않습니다(비밀번호 포함).
- 사용자 입력을 HTML로 그대로 넣지 않습니다(XSS). 프레임워크의 이스케이프를 우회하는 API(`innerHTML`, `dangerouslySetInnerHTML`)는 정화 후에만.

## 접근성 회복력

- 200% 확대, 글자 간격 조정(행간 1.5, 자간 0.12em, 단어 간격 0.16em)에서 잘림 없음.
- 고대비 모드(`forced-colors`)에서 테두리·포커스가 사라지지 않게. 배경색으로만 만든 버튼 경계는 이 모드에서 사라집니다.
- 화면 낭독기에서 동적 변화(오류, 결과 개수)가 `aria-live`로 알려지는지.

## 성능 회복력

- 느린 3G에서 첫 화면이 의미 있게 보이는지(스켈레톤, 텍스트 먼저).
- 이미지 실패 시 대체 표시, 레이아웃 유지.
- 무거운 목록·차트가 저사양 기기에서 멈추지 않게.

## 시험 방법

- 개발자 도구의 네트워크 제한(느린 3G, 오프라인)
- 아주 긴·빈·특수 문자(이모지, 따옴표, `<script>`) 데이터를 넣은 시험용 상태
- 권한별 계정으로 같은 화면
- `render-check --widths 320,1440`, 200% 확대

## 확인

- 위에서 해당하는 영역마다 무엇을 시험했고 결과가 어떤지 적습니다.
- 시험하지 못한 경로(실제 서버 오류 등)는 미확인으로 남깁니다.
