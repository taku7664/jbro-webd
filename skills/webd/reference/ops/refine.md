# 다듬기 명령: typeset · layout · colorize · animate · clarify · adapt

한 축만 집중해서 고치는 명령들입니다. 공통 규칙은 같고, 판단 기준은 각 `foundations/` 문서에 있습니다.

## 공통 규칙

1. **지금의 세계를 유지합니다.** 이 명령들은 정체성을 바꾸지 않습니다. 서체·팔레트를 통째로 바꿔야 할 정도면 `direction.md`로 가서 `DESIGN.md`를 갱신하겠다고 먼저 말합니다.
2. **두 갈래 진단**: 디자인 판단을 먼저 적고, 그다음 `detect.mjs`와 내부 브라우저의 페이지 검사(`verify.md` 2절) 결과를 합칩니다. 검사 결과가 판단을 끌고 가지 않게 순서를 지킵니다.
3. **방침 한 문단**을 쓰고 고칩니다. 방침 없이 값을 이것저것 바꾸지 않습니다.
4. **확인**은 렌더로. "좋아 보임"이 아니라 각 확인 항목에 근거(계산값, 스크린샷, 검사 결과)를 붙입니다.
5. 끝나면 `polish`를 권합니다.

## typeset — 글자

판단 기준: `foundations/typography.md`, `foundations/hangul.md`

- 진단: 권한·위계·스케일·읽기·스트레스(다섯 질문)
- 방침: 필요한 역할, 역할 사이의 대비, 줄 길이와 밀도, 유지할 서체·굵기, 성능·다국어·접근성 제약
- 흔한 처방: 역할 수 줄이기, 이웃 단계 차이 벌리기(크기+굵기 함께), 본문 줄 길이 제한, 제목 `balance`, 숫자 `tabular-nums`, 쓰지 않는 굵기 제거, 한글 대체 폰트 문제 해결
- 확인: 역할이 흐린 스크린샷에서도 구별되는가, 가장 좁은 폭에서 넘침 없음, `hangul-fallback` 0건

## layout — 구조·간격

판단 기준: `foundations/layout.md`

- 진단: 읽는 순서, 묶음, 리듬, 구조, 밀도, 적응, 극단(일곱 질문)
- 방침: 주 경로, 묶을 것·뗄 것, 이끄는 요소, 밀도·리듬, 폭별 구조 변화
- 흔한 처방: 상자 대신 가까움으로 묶기, 간격 단계 대비 키우기, 같은 크기 카드 반복을 중요도별 크기로, 지배 요소 하나 세우기, 제목 위 여백 > 아래
- 확인: 흐리게 본 화면에서 1순위·2순위·묶음이 순서대로, 포커스 순서 = 화면 순서

## colorize — 색

판단 기준: `foundations/color.md`

- 진단: 확정 브랜드 색, 현재 역할, 무채색 때문에 안 보이는 위계·상태, 대비 미달, 다크·데이터 필요 여부
- 방침: 온도, 지배 관계, 대비 폭, 분량
- 흔한 처방: 가장 강한 색에 한 영역·역할 주기, 주 행동 색을 장식에서 회수, 색 면 위 보조 글자를 그 면 색조로, 상태에 글자·아이콘 추가, 다크 모드 따로 설계
- 확인: 흑백 필터에서도 위계·주 행동, 색각 이상 시뮬레이션, 모든 상태 대비

## animate — 모션

판단 기준: `foundations/motion.md`

- 진단: 지금의 모션 언어, 상호작용 상태, 대상 기기, 성능 예산
- 방침: 연출 하나(있다면), 연속성이 필요한 변화, 피드백이 필요한 컨트롤, 예산
- 흔한 처방: 섹션마다 붙은 같은 등장 효과 제거 → 연출 하나, 상태 변화에 짧은 전환, bounce 제거, 레이아웃 속성 애니메이션을 transform으로, reduced-motion 경로 추가, 숨긴 채 시작하는 진입 제거
- 확인: 빼면 의미가 사라지는가, 중단·반복에 안전, reduced-motion, 애니메이션 멈춘 캡처에서도 내용 보임

## clarify — 글

판단 기준: `foundations/ux-writing.md`

- 진단: 버튼·링크·라벨·오류·빈 상태·로딩·완료·도움말 문구를 모두 모아 표로
- 방침: 메시지 위계(가장 중요한 한 문장), 목소리·어조·높임, 용어집
- 흔한 처방: "확인/제출"을 동작+대상으로, 오류에 무엇이·어떻게, 빈 상태에 다음 행동, 용어 통일, 상투 문구 제거, 높임 통일
- 확인: 버튼만 읽어도 결과를 아는가, 막다른 메시지 0개, 번역 길이에서 깨짐 없음
- 사실 주장(수치, 고객사, 기능)은 바꾸기 전에 묻습니다.

## adapt — 다른 화면·기기·매체

판단 기준: `foundations/responsive.md`

- 진단: 대상(모바일·태블릿·데스크톱·인쇄·이메일), 그 환경의 입력 방식과 제약, 무엇이 여전히 가장 중요한가
- 방침: 순서 바꾸기·접기·다시 흘리기·감추고 드러내기 중 무엇을 어디에
- 흔한 처방: 한 칼럼으로, 엄지 영역에 주 행동, 드롭다운 → 하단 시트, 표 → 가로 스크롤 또는 행 카드, 인쇄 스타일, 이메일용 표 레이아웃
- 확인: 대상 폭·매체에서 렌더, 사라진 정보 없음, 터치 동작은 실제(또는 합성) 터치로
