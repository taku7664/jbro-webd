# polish — 출시 전 마지막 손질

다듬기는 **몰래 하는 재디자인이 아닙니다.** 지금의 시각 세계, 콘텐츠, 동작, 범위 밖의 모든 것을 유지합니다. 개념 자체가 틀렸으면 그렇다고 말하고 재디자인이나 `bolder`를 제안합니다.

## 1. 체계를 확인한다

`DESIGN.md`, 토큰, 공유 컴포넌트, 이웃 화면의 패턴을 읽습니다. 형식적인 체계가 없으면 프로젝트에서 일관되게 쓰는 관습을 기준으로 삼습니다.

어긋남을 고치기 전에 종류를 나눕니다:

| 종류 | 고치는 곳 |
|---|---|
| 토큰이 없음 (재사용할 값인데 없음) | 토큰 추가 |
| 일회성 구현 (공유 컴포넌트가 있는데 따로 만듦) | 공유 컴포넌트로 교체 |
| 개념 불일치 (비슷한 화면과 흐름·위계가 다름) | 흐름을 맞추고, 범위가 크면 먼저 묻기 |
| 단순 결함 | 그 자리에서 수정 |

원인을 가장 좁은 올바른 수준에서 고칩니다.

## 2. 직접 써 본다

대표 크기(데스크톱·모바일)에서 기능을 처음부터 끝까지 써 봅니다. 확인할 것: 기능이 완결됐는가, 품질 기준과 남은 시간, 의도적으로 미완인 부분, 실제 사용자가 만날 상태·내용 길이·권한·입력 방식.

이전 critique 보고서가 있으면 P0·P1을 입력으로 씁니다. 그 뒤 파일이 바뀌었으면 독립적으로 다시 봅니다.

## 3. 순서

1. 막힌 작업, 데이터 손실, 오해를 부르는 상태, 접근 불가 경로
2. 빠진 상태: 로딩·빈·오류·성공·비활성·권한
3. 흐름·위계·반응형·체계 이탈
4. 시각·모션 불일치
5. 코드·자산 정리

한 구석을 완벽하게 만들고 나머지를 그 아래 품질로 두지 않습니다.

## 4. 경로 전체를 다듬는다

**흐름과 위계**
- 이웃 화면과 같은 용어, 공개 방식, 저장 동작(자동/버튼), 낙관적/비관적 패턴
- 주 작업과 현재 상태가 분명하되 모든 요소를 같은 무게로 평평하게 만들지 않기
- 도착·전환·빈 상태·회복 경로가 이어지는지

**레이아웃과 글자** (`layout.md`, `typography.md`, `hangul.md`)
- 그리드·간격 스케일 정렬, 수학적·시각적 정렬 모두
- 같은 역할의 글자는 같은 값
- 줄 길이, 줄바꿈, 번역 길이, 확대, 폰트 로딩
- 지금 보는 스크린샷만이 아니라 지원하는 모든 폭

**색·이미지·아이콘** (`color.md`)
- 의미 토큰, 테마 사이 같은 의미
- 모든 상태에서 글자·컨트롤·포커스 대비
- 아이콘 패밀리·선 두께·크기·시각 정렬 통일
- 이미지 비율·크기 지정으로 흔들림 방지, 의미 있는 대체 텍스트

**상호작용과 상태** (`interaction.md`)
- 모든 컨트롤의 기본·hover·focus·active·비활성·로딩·오류·성공
- 포커스 표시, Tab 순서, 라벨, 터치 대상
- 모션은 일관·중단 가능·가볍게. 다듬은 티를 내려고 애니메이션을 더하지 않음
- 긴 내용·없는 내용·번역·오프라인·느린 네트워크·권한 제한

**브라우저가 그리는 부분** (`craft-floor.md`)
- 텍스트 선택 색, 캐럿, 스크롤바, 포커스 링, 밑줄 오프셋, 표 숫자. 가장 싸게 완성도를 올리는 곳

**콘텐츠와 코드**
- 용어·문장 부호·높임 일관 (`ux-writing.md`). 사실 주장은 바꾸기 전에 묻기
- 디버그 출력, 죽은 코드, 쓰지 않는 import·스타일 제거
- 공유 컴포넌트가 있는 곳의 자체 구현 교체
- 정말 재사용되는 값만 토큰으로. 한 번 쓰는 예외를 위해 체계를 만들지 않음

## 5. 확인하고 끝낸다

- 마우스·키보드·터치로 경로 전체를 다시
- `detect.mjs`와 내부 브라우저의 페이지 검사(320·375·768·1440, 지원하면 dark, `verify.md` 2절)
- 콘솔 오류, 레이아웃 흔들림, 반응 지연
- `DESIGN.md`, 이웃 기능, 사용자 범위와 일치

마지막으로 diff를 봅니다. 실수로 바뀐 것, 고아 코드, 중복 값, 임시 파일을 지웁니다. 기능이 완결되고 경로 전체가 같은 수준으로 끝났을 때만 끝났다고 보고합니다.
