# 방향 정하기

방향은 **4개 축**에 대한 결정입니다. 모든 경로의 결과는 같은 형식의 `DESIGN.md`이고, 이 파일을 잠그기 전에는 화면 코드를 쓰지 않습니다.

| 축 | 정할 것 |
|---|---|
| 타입 | 디스플레이·본문 폰트(한글 폰트 포함), 스케일 비율, 굵기 범위, 행간 성격 |
| 색 | 기준 색상, 채도 성격, 배경 처리, 포인트 색 개수, 색 역할(primary, surface, muted, danger…) |
| 구성 | 그리드 성격, 밀도, 모서리 반경, 테두리·그림자 처리, 대칭 여부, 시선이 먼저 갈 요소 |
| 모션 | 쓰는 순간(한 번의 연출 vs 상태 변화만), 이징 성격, 길이 |

여기에 **시그니처 요소 하나**를 더합니다. 템플릿이라면 절대 넣지 않았을, 이 프로젝트에서만 나올 결정 하나입니다. 과감함은 여기에만 씁니다.

## 경로 고르기

| 상황 | 경로 |
|---|---|
| 사용자가 스타일 이름을 말함 | A. 스타일 사양 |
| 레퍼런스 이미지·스크린샷·URL을 줌 | B. 레퍼런스 토큰 추출 |
| 아무것도 없음 | C. 레퍼런스 2개 충돌 + 후보 비교 |
| 이미 잘 나온 화면이 하나 있음 | D. 화면에서 시스템 뽑기 |

경로를 섞어도 됩니다. 예: 스타일 사양(A)을 바탕으로 하되 색 축만 레퍼런스 이미지(B)에서 가져오기.

---

## A. 스타일 사양

1. `<스킬 폴더>/styles/INDEX.md`에서 이름에 맞는 파일 하나를 찾아 읽습니다. 다른 스타일 파일은 열지 않습니다.
2. 사양의 4축 값을 `DESIGN.md`로 옮깁니다.
3. 사양이 AI 티 목록과 겹치는 요소를 쓰면, 사용자가 그 스타일을 고른 것이므로 따릅니다(우선순위 2·3). 다만 접근성 하한선을 어기면 그 부분만 조정하고 알립니다.
4. 사양에 없는 축(예: 한글 폰트)은 사양의 성격에 맞춰 정하고, 정했다고 보고합니다.

## B. 레퍼런스 이미지에서 토큰 뽑기

이미지를 글로 묘사해서 다시 생성하면 정보가 크게 빠집니다. 이미지에서 **측정 가능한 값**을 뽑습니다.

1. 사용자에게 **무엇을 가져올지** 확인합니다. 기본 질문: "간격·색·타이포·레이아웃 중 어떤 걸 가져올까요?" 레이아웃까지 통째로 베끼는 것은 기본값이 아닙니다.
2. 가져올 축에 대해 다음을 뽑아 표로 정리합니다.
   - 타입: 제목·본문 크기 비율, 굵기 대비, 세리프/산세리프, 자간 성격
   - 색: 배경·본문·포인트 색 근사 hex, 채도 성격, 포인트 색 면적 비율
   - 간격: 기본 단위 추정(4/8px 등), 섹션 간격 대 요소 간격 비율, 밀도
   - 표면: 모서리 반경, 테두리 유무와 두께, 그림자 유무와 성격
3. 뽑은 값은 **추정치**로 표시합니다. 원본 CSS를 볼 수 있는 경우(사용자가 준 URL 등)에만 실제 값이라고 씁니다.
4. 가져오지 않는 축은 경로 C처럼 정합니다.
5. 다른 사이트의 로고·일러스트·카피는 가져오지 않습니다.

## C. 레퍼런스 2개 충돌

백지에서 시작하면 모델은 학습 데이터의 평균으로 갑니다. 레퍼런스 하나는 복제 대상이 되므로, **서로 다른 방향을 가진 2개**의 특정 성질을 겹쳐 그 사이를 노립니다.

1. 후보 3개를 만듭니다. 각 후보는 다음 한 줄로 시작합니다.
   > 근거: X의 [특정 성질] + Y의 [특정 성질]

   레퍼런스는 제품·출판물·사조·물건 모두 됩니다(지하철 노선도, 영수증, 문고판 표지, 도로 표지판). "모던 SaaS"·"깔끔한 미니멀"처럼 평균을 가리키는 말은 레퍼런스가 아닙니다. `context.md`에서 적어 둔 주제 세계의 물건을 우선 후보로 씁니다.
2. 후보끼리 레퍼런스 쌍과 기준 색상이 겹치지 않게 벌립니다.
3. 각 후보의 4축 + 시그니처를 짧게 적고, 필요하면 ASCII 와이어프레임을 붙입니다.
4. **고르기 전에** 세 후보를 함께 비평합니다.
   - 같은 브리프를 다른 프로젝트에 줬어도 나왔을 결정인가? 그렇다면 그 축을 고칩니다.
   - 모드에 맞는가? (Operate 화면에 과한 연출 등)
   - `ai-tells.md`의 항목을 이유 없이 쓰고 있는가?
5. 사용자에게 보여 주고 하나를 고르거나, 축 단위로 섞게 합니다("1번 타입 + 3번 색"). 사용자가 고정한 축은 모든 후보에 그대로 둡니다.
6. 마음에 드는 게 없으면 한 번만 다시 벌립니다. 그래도 없으면 무엇이 안 맞는지 물어 고정 축을 늘립니다.

## D. 화면에서 시스템 뽑기

이미 마음에 드는 화면(대개 메인 페이지)이 있을 때, 추상적인 사양보다 실제로 좋아 보이는 결과에서 시스템을 키우는 편이 낫습니다.

1. 그 화면의 실제 CSS·컴포넌트에서 값(색, 폰트, 크기, 간격, 반경, 그림자)을 읽습니다.
2. 반복되는 값을 토큰으로, 반복되는 구조를 컴포넌트로 정리합니다.
3. 값이 들쭉날쭉하면 가장 많이 쓰인 값으로 묶자고 제안합니다. 사용자가 승인하기 전에는 코드를 바꾸지 않습니다.
4. 결과를 `DESIGN.md`로 씁니다. 이후 화면은 이 파일을 기준으로 만들고 검사합니다.

## DESIGN.md 잠그기

`<스킬 폴더>/templates/DESIGN.md`를 복사해 채웁니다. 반드시 들어갈 것:

- 근거 한 줄 (스타일 이름, 또는 레퍼런스 충돌 문장, 또는 원본 화면)
- 4축 값과 CSS 변수 토큰
- 시그니처 요소
- **이 프로젝트의 금지 조건 2–5개**: "독특하게" 대신 "그라디언트 히어로 금지, 카드 중첩 금지"처럼 구체적으로
- 고정(pin)된 축과 기본값으로 둔 축

사용자가 확인하면 잠긴 것으로 보고 구현으로 넘어갑니다.
