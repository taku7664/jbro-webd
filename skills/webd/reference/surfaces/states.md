# 상태 화면: 404·오류·빈 화면·점검·로딩

어느 화면에나 붙는 상태들입니다. 판단 기준: `foundations/ux-writing.md`, `ops/onboard.md`, `foundations/motion.md`.

## 404

- 무엇이 일어났는지(페이지가 없음) + 그럴 수 있는 이유(주소 변경) + 할 일(검색, 첫 화면, 많이 찾는 곳 몇 개).
- 사이트의 일반 머리·내비게이션을 유지해 길을 잃지 않게.
- 표현 순간으로 쓰기 좋은 자리(`archetypes.md` register). 다만 길 찾기가 먼저.
- HTTP 상태 코드도 실제로 404를 반환.

## 서버 오류 (500)

- 사용자 탓이 아님을 분명히, 데이터 안전 여부, 다시 시도, 문제가 계속되면 연락처.
- 오류 ID를 작은 글씨로(지원 문의용).
- 농담 금지.

## 점검·장애

- 언제 끝나는지(알면 시각, 모르면 다음 안내 시각), 무엇이 안 되는지, 상태 페이지 링크.
- 자동 새로고침보다 "다시 확인" 버튼 + 시각 표시.

## 권한 없음 (403)

- 왜 볼 수 없는지, 누구에게 요청하는지, 요청 버튼이 있으면 그 자리에서.
- 다른 계정으로 전환하는 길.

## 오프라인

- 화면 위쪽의 얇은 알림 막대 정도로. 읽기는 계속되게.
- 연결이 돌아오면 알리고 대기 중이던 작업을 이어서.

## 빈 화면

종류별로 다르게(`ux-writing.md` 빈 상태 표). 처음 사용·다 처리함·결과 없음·권한 없음·불러오기 실패.

## 로딩

| 상황 | 표시 |
|---|---|
| 0.3초 안에 끝남 | 아무것도 표시하지 않음 (깜빡임 방지) |
| 내용 모양을 앎 | 스켈레톤 (실제 레이아웃과 같은 크기) |
| 짧은 행동 | 버튼 안 작은 스피너 + 버튼 비활성 |
| 시간이 걸리고 진행을 앎 | 진행률 + 남은 시간(정직하게) |
| 아주 김 | 백그라운드 처리 + 끝나면 알림 |

- 스켈레톤은 반짝임 애니메이션을 reduced-motion에서 멈춥니다.
- 로딩 문구는 실제 작업 이름("파일 3개를 올리는 중").

## 성공

- 무엇이 끝났는지 구체적으로. 일상 저장은 짧은 표시, 큰 이정표만 크게(`ops/intensity.md` delight).
- 다음 행동이 사용자 행동을 바꿀 때만 제안.

## 확인

- 각 상태에 다음 행동이 있는가? 막다른 화면이 없는가?
- 상태 화면에서도 내비게이션·검색이 동작하는가?
- 상태 문구에 상투어·농담·사용자 탓이 없는가?
