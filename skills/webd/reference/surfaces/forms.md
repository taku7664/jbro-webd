# 폼: 가입·로그인·결제·설정

모드: Operate. 판단 기준: `foundations/interaction.md`(폼 절), `foundations/ux-writing.md`, `foundations/ethics.md`.

## 공통

- 한 칼럼. 라벨은 입력 위, 항상 보이게.
- 묻는 것을 줄입니다. 칸마다 "지금 꼭 필요한가, 나중에 받아도 되나?"
- 관련 칸을 묶고(`fieldset` + `legend`), 묶음 사이 여백을 넉넉히.
- 알맞은 `type`·`inputmode`·`autocomplete`. 주소·카드·이름 자동 완성이 되면 입력 시간이 크게 줍니다.
- 검증은 칸을 떠날 때, 오류는 칸 바로 아래, 제출 시 요약 + 첫 오류로 포커스.
- 제출 버튼은 동작 이름("가입하기", "결제하기 32,000원"), 제출 중 로딩·중복 방지.
- 입력한 내용은 오류·새로고침에도 지키기(가능하면 임시 저장).

## 가입·로그인

- 소셜 로그인과 이메일 로그인의 무게를 정직하게. 둘 다 있다면 둘 다 같은 단계에.
- 비밀번호: 보기 토글, 규칙을 미리 보여 주고 입력 중 충족 표시, 붙여넣기·비밀번호 관리자 허용(`autocomplete="new-password"`/`current-password`).
- 인증 코드 칸: `autocomplete="one-time-code"`, `inputmode="numeric"`, 붙여넣기 지원, 칸을 쪼개더라도 한 번에 붙여넣어지게.
- 로그인 실패 문구는 어느 쪽이 틀렸는지 노출하지 않되 다음 행동(재설정)을 줍니다.
- 약관 동의: 필수와 선택을 나누고, 선택(마케팅 등)은 기본 해제. "모두 동의"가 선택 항목까지 몰래 묶지 않게(`ethics.md`).
- 가입 직후 바로 쓸 수 있게. 프로필 완성·팀 초대는 나중으로(`ops/onboard.md`).

## 결제

- 단계 표시(장바구니 → 배송 → 결제 → 확인), 지금 어디인지.
- **총액을 처음부터**: 상품, 배송비, 할인, 세금, 최종 금액. 마지막에 늘어나지 않게.
- 손님 결제 허용(가입 강요 금지)이 전환율에 큰 영향을 줍니다.
- 결제 수단 선택은 큰 대상, 선택 상태가 분명하게.
- 카드 번호: 공백 자동, 카드사 표시, 유효기간 `MM/YY`, CVC 도움말.
- 한국 서비스: 간편 결제·계좌 이체·휴대폰 결제 등 지역 수단, 주소 검색(우편번호) 흐름, 현금영수증·세금계산서.
- 결제 버튼에 금액. 누른 뒤에는 중복 결제 방지와 진행 표시.
- 완료 화면: 주문 번호, 받을 날짜, 영수증 이메일, 다음 행동(`styles/receipt.md`).
- 개인정보·결제 정보 화면에 장식 애니메이션·농담 금지.

## 설정

- 설정이 많으면 묶음별 섹션 + 왼쪽 목차(데스크톱) 또는 목록 → 상세(모바일).
- 저장 방식을 하나로: 바꾸면 바로 저장(토글, 선택) + "저장됨" 표시, 또는 섹션별 저장 버튼. 섞으면 사용자가 무엇이 저장됐는지 모릅니다.
- 위험한 설정(계정 삭제, 데이터 초기화)은 아래쪽 따로 구별된 영역, 확인 절차(`interaction.md` 파괴적 행동).
- 토글은 즉시 적용되는 켜기/끄기에만. 저장 버튼이 필요한 값에는 체크박스.
- 각 설정이 무엇을 바꾸는지 한 줄 설명.
