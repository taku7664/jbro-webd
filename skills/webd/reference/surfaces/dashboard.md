# 대시보드와 관리 화면

모드: Operate. 판단 기준: `modes.md` Operate, `foundations/data-viz.md`, `foundations/interaction.md`, `styles/instrument-panel.md`.

## 대시보드의 정의

**한눈에** 상태를 알고 다음 행동을 정하는 화면입니다. 1순위 지표를 보려고 스크롤해야 하면 보고서입니다.

## 구조

1. **맨 위**: 이 사람이 매일 묻는 질문의 답 3–7개. 각 지표는 값 + 비교 기준(지난 기간, 목표) + 상태(좋음/주의/나쁨을 글자로).
2. **그 아래**: 그 지표들의 추세.
3. **세부**: 분해 차트, 표, 드릴다운.
4. **행동**: 문제가 보이면 바로 할 수 있는 일(필터, 담당자 지정, 상세로 이동).

- 지표 카드를 같은 크기로 줄 세우지 말고 **중요도에 따라 크기를 다르게**.
- 숫자 하나만 크게 두는 "히어로 지표"는 비교 기준 없이는 의미가 없습니다.
- 장식용 스파크라인·진행 링·원형 게이지 금지.

## 내비게이션

- 데스크톱: 상단 막대 + 왼쪽 사이드 내비(접을 수 있게), 현재 위치 표시, 브레드크럼.
- 항목이 많으면 명령 팔레트(⌘K / Ctrl+K)로 이동·실행.
- 모바일: 사이드 내비 → 하단 탭(5개 이하) 또는 메뉴. 대시보드는 핵심 지표만 위로, 나머지는 접기.

## 표

- 숫자 열 오른쪽 정렬 + `tabular-nums`, 글자 열 왼쪽 정렬.
- 머리 고정, 첫 열 고정(가로 스크롤 시).
- 정렬 가능한 열은 표시와 현재 정렬 방향.
- 행 선택 + 일괄 작업. 행 위 hover 행동은 키보드·터치에서도 닿게.
- 50행 넘으면 페이지네이션 또는 가상 스크롤. 지금 몇 개 중 몇 개인지.
- 빈 표·필터 결과 없음·불러오기 실패 상태(`foundations/ux-writing.md`).
- 줄 구분은 아주 옅게 또는 여백만. 이미 여백으로 나뉜 표에 굵은 테두리를 더하지 않습니다.

## 필터·검색

- 적용 중인 필터를 칩으로 보이게, 하나씩·전체 해제.
- 필터 상태를 URL에 남겨 공유·새로고침에도 유지.
- 검색은 입력하면서 결과(debounce), 결과 개수 알림(`aria-live`).

## 밀도

- 촘촘해도 됩니다. 다만 터치 대상 크기와 읽기 대비는 지킵니다.
- 사용자에게 밀도 선택(편안/촘촘)을 주는 것도 방법입니다.

## 실시간 갱신

- 값이 바뀔 때 화면이 튀지 않게(자리 고정, 숫자 폭 고정).
- 바뀐 곳을 잠깐 표시(테두리 강조 600ms)하되 깜빡이지 않게.
- 마지막 갱신 시각 표시, 연결 끊김 표시.
- 화면 낭독기에는 중요한 변화(경보)만 알립니다.

## 확인

- 첫 화면에서 스크롤 없이 1순위 질문의 답이 보이는가?
- 모든 지표에 비교 기준이 있는가?
- 상태를 색만으로 표시한 곳이 없는가?
- 표가 375px에서 쓸 수 있는가?
- 키보드만으로 필터·정렬·행 선택·일괄 작업이 되는가?
