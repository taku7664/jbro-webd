# WebD

"모델이 아무 결정도 안 했을 때 나오는 화면"을 피하고, 이 프로젝트를 위해 내린 결정이 보이는 웹 UI를 만듭니다. 이 문서는 길잡이만 담고, 단계별 지침은 `reference/`에 나눠 두었습니다. **필요한 단계의 파일만, 그 단계 직전에 읽습니다.**

`<스킬 폴더>`는 이 스킬을 불러올 때 표시되는 base directory입니다.

## 우선순위

결정이 부딪히면 위가 이깁니다.

1. **접근성 하한선**: 대비, 키보드 포커스, reduced-motion, 확대 허용. 어떤 스타일 지정도 넘지 못합니다.
2. **사용자가 고정(pin)한 것**: 직접 말한 폰트·색·스타일 이름·레퍼런스 이미지. 금지 목록에 있는 항목이라도 사용자가 원하면 따릅니다.
3. **선택한 스타일 사양** (`styles/`) 또는 잠근 `DESIGN.md`
4. **AI 티 목록** (`reference/ai-tells.md`): 사용자가 비워 둔 축에서만 적용합니다.
5. **업종·관례 기본값**: 마지막 수단입니다. 기본값을 쓸 때는 쓴다고 밝힙니다.

## 흐름

```
맥락 → 방향 → 구현(2단계) → 검증
```

| 단계 | 할 일 | 읽을 파일 |
|---|---|---|
| 맥락 | 대상·목표·화면 모드를 정하고 `PRODUCT.md`에 남김 | `reference/context.md`, `reference/modes.md` |
| 방향 | 스타일 지정·레퍼런스 이미지·백지 중 하나로 방향을 정하고 `DESIGN.md`를 잠금 | `reference/direction.md`, 필요하면 `styles/INDEX.md` |
| 구현 | 1차 구조·콘텐츠 → 2차 타입·색·간격 | `reference/build.md`, 2차 직전에 `reference/craft-floor.md` |
| 검증 | 자동 검사 → 렌더 확인 → 비평 → 수정 스펙 | `reference/verify.md`, `reference/ai-tells.md` |

## 요청별 진입점

- **새 화면·새 프로젝트**: 맥락부터 차례대로 진행합니다. `PRODUCT.md`가 이미 있으면 읽고 맥락 단계를 건너뜁니다.
- **스타일 이름을 지정함** ("bento 스타일로"): `styles/INDEX.md`에서 파일을 찾아 그 파일 하나만 읽습니다. 목록에 없으면 비슷한 스타일을 제안하고 고르게 합니다.
- **레퍼런스 이미지·스크린샷을 줌**: 글로 다시 설명하지 말고 `reference/direction.md`의 「레퍼런스 이미지에서 토큰 뽑기」를 따릅니다.
- **기존 화면 다듬기**: 기존 정체성(색·폰트·카피·동작)을 유지합니다. 범위 밖은 건드리지 않습니다. `DESIGN.md`가 없으면 현재 코드에서 토큰을 읽어 기준으로 삼습니다.
- **기존 화면 갈아엎기**: 콘텐츠·기능·제약은 유지하고 겉모습만 새로 정합니다. 방향 단계부터 진행합니다.
- **리뷰·비평만**: `reference/verify.md`만 읽고 결과를 보고합니다. 고치라는 요청이 없으면 코드를 바꾸지 않습니다.

## 지키는 것

- **기존 파일을 덮어쓰지 않습니다.** `PRODUCT.md`·`DESIGN.md`가 이미 있으면 읽고 이어 씁니다. 바꿔야 하면 무엇을 왜 바꾸는지 먼저 말합니다.
- **사실이 아닌 카피를 지어내지 않습니다.** 수치·고객사·후기 같은 주장은 사용자가 준 것만 씁니다. 없으면 자리 표시로 남기고 알립니다.
- **"독특하게"를 형용사로 처리하지 않습니다.** 결정은 토큰·규칙·금지 조건처럼 확인할 수 있는 형태로 남깁니다.
- **렌더를 직접 봅니다.** 브라우저·스크린샷 도구가 있으면 실제 화면으로 확인하고, 없으면 확인하지 못했다고 보고합니다.
- **검증 결과를 꾸미지 않습니다.** 자동 검사가 못 잡는 항목, 직접 보지 못한 해상도는 미확인으로 남깁니다.
