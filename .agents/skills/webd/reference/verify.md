# 검증

자동 검사와 비평으로 명백한 문제를 미리 고칩니다. 컴포넌트와 화면은 각각 사용자 확인을 거칩니다.

## 1. 정적 검사

```
node "<스킬 폴더>/scripts/detect.mjs" <파일 또는 폴더> [--allow 규칙,규칙] [--json]
```

- `--list-rules`로 검사 목록을 봅니다. 종료 코드 0은 high·medium 0건, 2는 1건 이상, 1은 사용 오류입니다.
- `DESIGN.md`의 「고정」에 적은 의도적인 결정만 `--allow`로 제외합니다. 예를 들어 장부 합계 위 이중선을 선택했다면 이유와 해당 규칙을 적습니다.
- `ai-tells.md`와 대응해 거른 항목을 기록합니다. 카드 반복·시각 위계·숨김·대비는 실제 렌더에서 다시 봅니다.
- 프로젝트에 Impeccable이 이미 설치돼 있으면 `npx impeccable detect`를 함께 쓸 수 있습니다. 새로 설치하려면 사용자 승인을 받습니다.

## 2. 렌더 확인

1. 시안과 검사 모듈을 같은 로컬 서버에서 제공하고 Codex 내부 브라우저로 시안을 엽니다. 필요한 파일만 `127.0.0.1`에 제공하며 실제로 열린 포트를 확인합니다.
2. 프로젝트가 지원하는 폭(웹 기준 375·768·1440px, 필요하면 1024px)과 라이트·다크 모드를 맞춥니다. 폰트가 로드되고 진입 애니메이션이 끝나면 맨 위에서 아래 검사를 실행합니다. 결과의 실제 폭·높이·스크롤 위치·색 모드를 기록합니다.
3. `scripts/browser/page-checks.mjs`의 `inspectPage()`가 현재 화면의 대비, 작은 글자(SVG 포함), 가로·앱 틀 세로 넘침, 터치 대상, 보이는 글자 수, 테두리 상자·채움 버튼·글자 크기 수, 한글 폰트 후보와 현재 포커스를 반환합니다. 문서와 내부 패널을 직접 스크롤하고 다시 실행해 범위를 넓힙니다. 첫 화면 수치는 맨 위에서 기록합니다.

서버 루트에 저장소를 연결한 경우, 페이지에서 자바스크립트를 실행할 수 있는 콘솔에 아래 코드를 사용합니다. 콘솔 실행이 없는 브라우저에서는 검증용 시안 사본에 같은 코드를 모듈 스크립트로 붙여 JSON을 표시하고 실제 배포 파일에는 남기지 않습니다.

```js
const { inspectPage } = await import("/skills/webd/scripts/browser/page-checks.mjs");
await document.fonts.ready;
console.log(JSON.stringify(inspectPage(), null, 2));
```

모듈 사본에서 결과를 화면에 표시할 때는 `inspectPage()`를 먼저 실행한 다음 결과를 출력합니다. 검사 결과 표시가 시안의 문서 높이와 넘침에 영향을 주지 않도록 합니다.

| 항목 | 내부 브라우저 확인 | 헤드리스에서 자동화하는 항목 |
|---|---|---|
| 실제 한글 렌더 폰트 | JSON의 `hangul`에 나온 요소·스택을 확인합니다. `document.fonts.check('16px "폰트명"', '가나다')`나 `document.fonts`의 선언·로드 상태를 확인하고, 필요하면 같은 글자의 폭을 대체 스택과 비교합니다. 로드나 너비 차이만으로 실제 그린 폰트와 글리프 대체 여부를 확정할 수는 없습니다. | CDP `CSS.getPlatformFontsForNode` |
| Tab·조작 | 실제 Tab과 키보드 입력으로 이동하고 포커스 표시, 저장·제출·되돌리기 상태를 봅니다. `inspectPage().focus`는 이미 포커스된 요소의 outline·shadow만 읽습니다. | Tab 키 주입과 포커스 탐색 |
| 폭·높이와 모드 | 창이나 브라우저 뷰포트 설정을 바꾸고, 앱의 모드 토글 또는 시스템·브라우저 색 모드 설정을 사용합니다. 바꿀 수 없는 조건은 미확인으로 기록합니다. | 화면 크기와 `prefers-color-scheme` 에뮬레이션 |
| 나가기 경고 | 검증용 데이터로 나가기 경고가 뜨는지 보고 취소합니다. | 대화상자 감지·자동 수락 |
| 화면 캡처 | 내부 브라우저의 스크린샷으로 첫 화면, 좁은 폭, 스크롤 패널 아래를 봅니다. `bg-uncertain`인 이미지·그라디언트 위 글자는 직접 확인합니다. | 첫 화면·전체·앱 틀 펼침 캡처 |

선택형 헤드리스 명령은 `node "<스킬 폴더>/scripts/render-check.mjs" <파일 또는 URL> --widths 375,1440 --scheme light,dark --json`입니다. `--height`로 높이를, `--out`으로 스크린샷 폴더를 지정합니다. 설치된 Chrome·Edge·Chromium을 쓸 수 없으면 내부 브라우저 경로를 사용합니다.

## 3. 자동 비평으로 거르기

Impeccable의 finish reviewer와 frontend-design의 자기 비평은 무인 실행을 전제로 합니다. WebD에서는 대비·겹침·잘림·넘침·위계 붕괴를 미리 고쳐 사용자 검토 시간을 줄이는 데 씁니다. 보고에는 **거른 항목**, 남은 문제, 미확인 범위를 적습니다.

- `PRODUCT.md`의 목표와 필수 동작, `DESIGN.md`의 제약을 화면과 대조합니다. 저장·제출·되돌리기 같은 동작은 눌러서 상태가 바뀌는지 확인합니다.
- `visual-quality.md` 9절의 질문으로 시각 위계·시그니처를 확인하고, `craft-floor.md`와 `ai-tells.md`를 대조합니다.
- 여러 문제를 한 번에 찾고 같은 조건에서 수정 전후를 다시 봅니다. 지적은 위치·문제·구체적인 수정·근거로 기록합니다.

## 4. 사용자 검토와 확정

- 현재 컴포넌트를 라이브러리에 저장해 `webd-library` 편집기로 엽니다. 피드백을 반영하고 사용자가 그 버전을 확정하면 다음 컴포넌트로 갑니다.
- 확정한 컴포넌트를 조립하고 연결 상태와 전체 작업 흐름을 거른 뒤 화면 단위로 사용자 검토를 받습니다. 사용자가 조립된 화면을 확정하면 완성으로 기록합니다.
- 무인 실행이나 사용자 답변이 오지 않은 경우 현재 컴포넌트 또는 화면을 **사용자 검토 대기**로 남깁니다.
