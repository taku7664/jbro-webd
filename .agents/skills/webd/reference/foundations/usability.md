# 사용성과 접근성

예쁜 화면은 사용성 문제를 가립니다. 보기 좋은 시안은 사용성 평가 점수를 부풀리고, 실제 결함을 테스트에서 놓치게 만듭니다(심미적 사용성 효과). 그래서 **사용성을 먼저 고치고, 그다음 다듬습니다.**

## Nielsen의 10가지 휴리스틱

비평(`ops/critique.md`)에서 점수를 매기는 뼈대입니다.

1. **시스템 상태를 보여 준다**: 지금 무슨 일이 일어나는지 제때 알린다. (저장됨, 처리 중, 3단계 중 2단계)
2. **현실과 같은 말**: 사용자의 단어·관습을 쓴다. 시스템 용어 금지.
3. **사용자의 통제와 자유**: 되돌리기, 분명한 나가기.
4. **일관성과 표준**: 플랫폼·제품 내부의 관습을 따른다.
5. **오류 예방**: 문제가 생기기 전에 막는다(제약, 좋은 기본값, 확인).
6. **기억보다 알아보기**: 선택지를 보여 주고 기억 부담을 줄인다.
7. **유연성과 효율**: 숙련자를 위한 지름길(단축키, 일괄 작업).
8. **심미적이고 최소한의 디자인**: 관련 없는 정보가 주의를 빼앗지 않는다.
9. **오류를 알아보고 진단하고 회복하게**: 쉬운 말과 빠져나갈 길.
10. **도움말과 문서**: 필요할 때 찾을 수 있고 작업 중심.

## 게슈탈트: 무엇을 한 덩어리로 보나

- **근접**: 가까운 것은 함께. 묶음을 만드는 가장 강한 수단(`layout.md`).
- **유사**: 같은 모양·색·크기는 같은 종류.
- **공통 영역**: 같은 상자·배경 안은 함께. 근접으로 안 될 때만.
- **연속**: 선이나 정렬을 따라 시선이 흐른다.
- **폐합**: 비어 있어도 모양을 완성해서 본다.
- **전경-배경**: 무엇이 앞에 있는지 분명해야 한다.

## 접근성 기본 (WCAG 2.2 AA 중심)

자동 검사가 잡는 것은 일부입니다. 통과해도 쓰기 어려울 수 있으니 직접 키보드·화면 낭독으로 써 봅니다.

**인식할 수 있게**
- 대비: 본문 4.5, 큰 글자 3, 컨트롤·아이콘·포커스 표시 3 (`color.md`)
- 의미 있는 이미지에 대체 텍스트, 장식은 `alt=""`
- 색만으로 의미 전달 금지
- 200% 확대·글자 간격 조정에서 내용이 잘리지 않음
- 영상 자막, 소리만으로 정보 전달 금지

**조작할 수 있게**
- 키보드만으로 모든 기능. 포커스 표시가 늘 보임. 고정 헤더·배너가 포커스된 요소를 가리지 않음
- 본문으로 건너뛰기 링크
- 포인터 대상 최소 24×24px(WCAG 2.2), 터치는 44×44px 권장
- 끌기(drag)만으로 하는 동작에는 클릭·키보드 대안
- 자동으로 움직이는 내용에 멈춤 수단, 번쩍임 금지
- 시간 제한이 있으면 연장 수단

**이해할 수 있게**
- `<html lang>` 지정
- 라벨·지시가 입력 앞에. 오류는 무엇이·어떻게
- 같은 기능은 화면마다 같은 이름·위치. 도움말 위치 일관
- 이미 입력한 정보를 다시 묻지 않음
- 인증에서 붙여넣기·비밀번호 관리자 허용, 기억력 퍼즐만으로 인증하지 않음

**견고하게**
- 의미에 맞는 HTML(`button`, `a`, `nav`, `main`, `h1`–`h6`, `label`). `div`에 클릭을 붙이지 않음
- 제목 단계를 건너뛰지 않음
- 아이콘 버튼에 접근 가능한 이름
- 바뀌는 상태·개수는 `aria-live`로 한 문장으로 알림(초점을 옮기지 않고)
- ARIA는 HTML로 안 될 때만. 잘못된 ARIA는 없는 것보다 나쁨

## 규칙을 깰 때

- 정말 새로운 범주라 기존 관습이 없을 때
- 기존 관습이 해로울 때
- 한 번 배우면 되는 비용을 치를 만큼 차별화 가치가 클 때
- 매일 깊게 쓰는 도구라 학습 비용이 금방 흡수될 때

깰 때는 무엇을 왜 깼는지 `DESIGN.md`에 적습니다.
