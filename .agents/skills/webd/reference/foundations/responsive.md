# 반응형과 적응

반응형은 큰 화면을 줄이는 일이 아니라, **화면·입력 방식·환경이 바뀌어도 무엇이 여전히 중요한지**에 따라 구조를 다시 짜는 일입니다.

## 원칙

- **좁은 화면부터** 씁니다(`min-width` 쿼리). 좁은 화면에서 무엇을 남길지 정하면 우선순위가 분명해집니다.
- **브레이크포인트는 내용이 깨지는 곳에.** 특정 기기 폭(768, 1024)에 맞추지 않고, 창을 늘이고 줄이며 레이아웃이 망가지는 지점에 둡니다.
- 고정 폭 컨테이너(`width: 960px`) 대신 `width: min(100%, 960px)` 또는 `max-width` + 여백.
- 좁은 화면 사용자에게서 내용을 **빼지 않습니다.** 접기, 순서 바꾸기, 요약하기로 형태만 바꿉니다. `display: none`으로 정보를 없애면 그 사용자는 그 정보를 영영 못 봅니다.
- 가능하면 **내재적 레이아웃**: `grid-template-columns: repeat(auto-fit, minmax(16rem, 1fr))`처럼 공간에 따라 저절로 흐르게 하고, 사이드바 등장 같은 큰 구조 변화에만 브레이크포인트를 씁니다.
- 여러 맥락에 들어가는 컴포넌트는 **컨테이너 쿼리**(`@container`)로 자기 칸 폭에 반응하게 합니다.

## 확인할 폭

| 폭 | 대표 |
|---|---|
| 320 | 가장 좁은 휴대폰 (확대 200%의 640px 화면과도 비슷) |
| 375–414 | 일반 휴대폰 |
| 768 | 세로 태블릿, 좁은 창 |
| 1024–1280 | 가로 태블릿, 노트북 |
| 1440 이상 | 넓은 모니터. 줄 길이가 너무 길어지지 않는지 |

최소 375와 1440, 가능하면 320·768도 봅니다(`render-check --widths 320,375,768,1440`).

## 좁은 화면으로

- 여러 칼럼 → 한 칼럼, 나란히 → 세로로.
- 주 내용 먼저. 보조 내용은 탭·접기·"더 보기"로.
- 내비게이션: 항목이 5개 이하면 하단 탭, 많으면 메뉴 버튼 + 전체 화면 메뉴. 현재 위치를 늘 보여 줍니다.
- 드롭다운 대신 하단 시트, 작은 링크 대신 큰 버튼.
- 엄지가 닿는 아래쪽에 주요 행동.
- 표: 가로 스크롤 컨테이너(첫 열 고정) 또는 행마다 카드 형태로 바꾸기. 비교가 목적이면 가로 스크롤이 낫습니다.
- 본문 16px 이상 유지. 줄이지 않습니다.

## 넓은 화면으로

- 늘어난 공간을 줄 길이로 쓰지 않습니다. 본문 칼럼 폭은 그대로 두고 여백·보조 칼럼·다단 배치로.
- 사이드 내비게이션, 목록과 상세를 나란히(master-detail), 미리보기 패널.
- 마우스·키보드 사용자를 위한 hover 상태, 단축키, 우클릭 메뉴는 보너스. 기능의 유일한 경로가 되면 안 됩니다.

## 입력 방식

- `@media (pointer: coarse)`: 터치. 대상 44px 이상, 간격 넓게, hover 의존 제거.
- `@media (hover: hover)`: hover 효과는 이 안에서만. 터치 기기에서 hover가 "붙어 있는" 문제를 막습니다.
- 키보드만으로 모든 기능에 닿아야 합니다.

## 글자와 이미지

- 큰 제목만 `clamp()`로 흐르게. 본문·라벨은 고정.
- 같은 이미지의 해상도만 다르면 `srcset` + `sizes`. 구도가 바뀌어야 하면(좁은 화면에서 인물 중심으로 자름) `<picture>`.
- 이미지·영상에 `width`/`height` 또는 `aspect-ratio`를 줘서 로딩 중 흔들림(CLS)을 막습니다.

## 안전 영역과 뷰포트

- 노치·둥근 모서리 기기에서 고정 요소·전체 폭 요소에 `padding: env(safe-area-inset-*)`. `viewport-fit=cover`와 함께.
- 휴대폰 주소창 때문에 `100vh`가 화면보다 깁니다. `100dvh`(또는 `svh`)를 씁니다.
- 확대를 막지 않습니다(`user-scalable=no` 금지).

## 화면 밖 매체

**인쇄** (`@media print`)
- 내비게이션·버튼·광고 제거, 흑백에서도 읽히게.
- 링크 주소를 펼쳐 보여 주기(`a[href]::after { content: " (" attr(href) ")"; }`), 접힌 내용 펼치기.
- 표·그림이 페이지 사이에서 잘리지 않게 `break-inside: avoid`.

**이메일**
- 폭 600px 안팎, 한 칼럼, 표 기반 레이아웃, 인라인 CSS. 많은 메일 앱이 최신 CSS를 지원하지 않습니다.
- hover 없음. 큰 버튼, 복잡한 동작은 웹으로 보내는 링크.
- 이미지가 차단돼도 내용이 전달되게(대체 텍스트, 배경색).

## 확인

- 320·375·768·1440에서 가로 스크롤이 없는가?
- 좁은 화면에서 사라진 정보가 없는가?
- 화면 순서와 포커스 순서가 모든 폭에서 맞는가?
- 200% 확대에서 내용이 잘리거나 겹치지 않는가?
- 터치 기기에서 hover 전용 기능이 없는가?
