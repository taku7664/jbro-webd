# 한글 타이포그래피

한국어 화면에서 계속 문제가 되는 지점을 모았습니다. `typography.md`의 일반 원칙 위에 덧붙여 읽습니다. 서체 제공처·라이선스는 바뀔 수 있으므로 쓰기 전에 배포처에서 확인합니다.

## 기본 설정

```html
<html lang="ko">                   <!-- 한중일 공용 한자·문장 부호 글리프 선택과 화면 낭독에 영향 -->
```

```css
body {
  word-break: keep-all;            /* 어절 단위로 줄바꿈. 조사·어미가 다음 줄로 떨어지지 않음 */
  overflow-wrap: anywhere;         /* 긴 URL·영단어가 칸을 넘지 않게 */
  line-height: 1.7;                /* 한글 본문 1.6–1.8 */
  letter-spacing: 0;               /* 본문은 0. 큰 제목만 -0.01 ~ -0.02em */
}
```

- `keep-all`은 좁은 칼럼에서 줄 끝이 크게 비는 대신 어절이 깨지지 않습니다. 좁은 버튼·칩처럼 공간이 아주 좁으면 그 요소만 `normal`로 둡니다.
- `<html lang="ko">`가 없으면 일부 환경에서 한자·문장 부호가 중국어·일본어 글리프로 나옵니다.

## 줄 길이

- `ch` 단위는 숫자 "0"의 폭이라 한글 글자 폭(대략 1em)과 다릅니다. 한글 본문은 **한 줄 35–45자**가 편합니다.
- CSS로는 `max-width: 36em` 안팎(본문 크기 기준) 또는 `65–72ch`가 비슷한 길이가 됩니다. 실제 렌더에서 한 줄 글자 수를 세어 확인합니다.

## 크기와 굵기

- 한글은 같은 px에서 라틴보다 글자 면이 꽉 차 보입니다. 본문 16–17px, 촘촘한 화면의 라벨 13–14px가 하한입니다.
- 한글 서체의 굵은 굵기(700 이상)는 획이 뭉치기 쉽습니다. 작은 크기(14px 이하)에서는 600 이하를 우선 시험합니다.
- 큰 제목은 700–900이 힘 있게 보이지만, 디스플레이 서체(예: 검은고딕 계열)는 400 하나만 있는 경우가 많습니다. 없는 굵기를 `font-weight: 700`으로 요청하면 브라우저가 가짜 볼드를 만듭니다.

## 이탤릭과 대문자

- 한글에는 이탤릭이 없습니다. `font-style: italic`을 주면 브라우저가 기울인 가짜 글자를 만듭니다. 강조는 굵기·색·배경으로.
- `text-transform: uppercase`는 한글에 아무 효과가 없습니다. 영문 라벨용 규칙이 한글 라벨에 붙어 있으면 의도와 다르게 보입니다.

## 라틴·숫자와 섞어 쓰기

- 한 화면에 한글과 라틴·숫자가 섞이면 두 서체의 높이·굵기가 어긋나기 쉽습니다.
  - **한 패밀리로 두 문자를 다 가진 서체**(한글과 라틴을 같이 설계한 서체)를 우선합니다.
  - 라틴 서체를 앞에 두고 한글 서체를 뒤에 두는 스택(`"Latin Font", "Korean Font"`)을 쓰면 라틴·숫자는 앞 서체, 한글은 뒤 서체로 나옵니다. 크기가 어긋나면 `@font-face`의 `size-adjust`로 맞춥니다.
- 일부 한글 서체의 라틴 글리프는 흔한 기본 서체를 바탕으로 만들어졌습니다. 영문 비중이 큰 화면이면 라틴 부분의 인상도 따로 봅니다.
- **라틴 전용 서체에 한글이 들어가면** 다른 폰트로 대체돼 자간·굵기가 어긋납니다(시험에서 반복 확인). 모노스페이스·영문 디스플레이는 숫자·영문에만 쓰거나 바로 뒤에 어울리는 한글 서체를 둡니다. `render-check`의 `hangul-fallback`이 잡습니다.

## 서체 고르기 (성격별 예)

목록은 출발점입니다. 실제 제공처·라이선스·제공 굵기를 확인하고 씁니다.

| 성격 | 예 | 쓰임 |
|---|---|---|
| 중립 고딕 (본문 기본기) | Pretendard, SUIT, Noto Sans KR, IBM Plex Sans KR, Spoqa Han Sans Neo, Wanted Sans | 앱 UI, 대시보드, 본문 |
| 기하·단정한 고딕 | Gothic A1, 나눔스퀘어 네오 | 제목, 브랜드 |
| 명조 (읽기·격식) | Noto Serif KR, 나눔명조, 마루부리, Hahmlet, 고운바탕 | 긴 글, 에디토리얼, 문학·문화 |
| 굵은 디스플레이 | Black Han Sans, Do Hyeon, Gasoek One, Bagel Fat One | 포스터, 행사, 캠페인 제목 |
| 둥근·친근 | Jua, 고운돋움, Sunflower | 어린이·생활 서비스 |
| 손글씨 | Nanum Pen Script, Gaegu, Hi Melody | 주석·짧은 강조만 |
| 고정폭 | Nanum Gothic Coding, D2Coding | 코드, 영수증 같은 매체 |

- **흔한 기본값 주의**: 한국어 화면에서 이유 없이 고른 Noto Sans KR·Pretendard도 영문 화면의 Inter와 같은 신호를 줍니다. 좋은 서체이지만, 방향을 정했다면 그 방향의 성격을 가진 서체를 먼저 찾습니다.
- 명조를 본문에 쓸 때는 고딕보다 크기를 1px, 행간을 0.1 정도 더 줍니다.

## 파일 크기와 부분 집합

- 한글 서체 한 굵기는 수 MB가 될 수 있습니다(완성형 11,172자). 그대로 불러오면 첫 화면이 느려집니다.
- 다음 중 하나를 씁니다.
  - 배포처가 제공하는 **동적 부분 집합**(unicode-range로 나뉜 여러 조각, 필요한 조각만 다운로드)
  - 정적 사이트라면 실제로 쓰는 글자만 남긴 **부분 집합 파일**을 직접 만들기
  - 디스플레이 서체는 제목에 쓰는 글자만 부분 집합으로
- 굵기는 2–3개로 제한합니다. 가변 폰트 하나가 굵기 3개보다 클 수 있으니 실제 바이트를 비교합니다.

## 문장 부호와 표기

- 따옴표: 본문은 “ ”, ‘ ’. 곧은따옴표(" ')는 코드에서만.
- 가운뎃점(·)은 나열에. 메타 정보마다 `A · B · C`로 이어 붙이면 AI 티가 됩니다(`ai-tells.md`).
- 줄임표는 `…` 한 글자.
- 숫자와 단위: 화면 안에서 한 가지로 통일합니다(`10kg` 또는 `10 kg`). 금액은 `12,000원`.
- 날짜: 화면 안에서 한 형식으로(`2026. 11. 9.` 또는 `2026-11-09` 또는 `11월 9일 (일)`). 요일은 괄호 안에.
- 문장 끝 마침표: 제목·버튼·라벨에는 찍지 않고, 두 문장 이상인 안내문에는 찍습니다.

## 강조와 리듬

- 한글은 대문자·이탤릭이 없으므로 위계가 **크기·굵기·색·간격**에 더 크게 의존합니다. 이웃 단계 차이를 라틴 화면보다 조금 더 벌립니다.
- 긴 한글 제목은 의미 단위로 줄을 끊는 것이 읽기 쉽습니다. `text-wrap: balance`와 `keep-all`을 함께 쓰고, 중요한 제목은 모든 폭에서 확인합니다.

- 한글에 이탤릭·대문자 변환이 걸린 곳이 없는가?
- 없는 굵기를 요청해 가짜 볼드가 생긴 곳이 없는가?
- 폰트 파일 합계가 첫 화면 예산 안인가?
