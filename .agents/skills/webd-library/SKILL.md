# WebD 라이브러리

UI 조각을 단독으로 열리는 HTML로 저장하고, 목록 페이지에서 미리보기·검색·기간 필터·정렬로 찾아 다른 곳에서 다시 씁니다.

## 등록 단위

- **사용자가 가리킨 조각 하나를 따로 가져다 쓸 수 있게 저장합니다.** 제목, 설명, 조작 안내, 상태 견본, 전체 화면과 조합 예제는 검토 화면에서만 보여 줍니다. 목록·보기 요청은 읽기 작업으로 처리합니다.
- **버튼 한 개를 저장할 때는 실제 조작 컨트롤 한 개만 넣습니다.** 버튼 모양 링크는 `href`가 있는 링크 한 개를 씁니다. 같은 버튼의 기본·호버·눌림·선택은 한 컨트롤의 CSS 또는 동작으로 재현합니다. 버튼 복제본과 상태표를 여러 개 두지 않습니다. 아이콘은 그 버튼 자체의 일부일 때만 내부에 둡니다.
- 메뉴·표·폼처럼 여러 요소가 함께 한 역할을 하는 경우에는 그 조각의 경계를 정하고 해당 분류로 저장합니다. 버튼 검사를 피하려고 분류를 바꾸지 않습니다.
- 스프라이트 시트·PNG·좌표 JSON·캡처는 별도 산출 경로에 둡니다. 같은 에셋의 상태를 한 시트에 묶을 수 있으며, 서로 다른 에셋은 별도로 내보냅니다. 에셋 산출 요청만으로 라이브러리에 등록하지 않습니다.

`<스킬 폴더>`는 현재 읽는 `SKILL.md`가 들어 있는 폴더입니다. 스크립트는 의존성 없는 Node 18+ 스크립트입니다.

```
node "<스킬 폴더>/scripts/library.mjs" <명령> [옵션]
```

## 저장 위치

기본은 사용자 홈의 `~/.webd/library/`입니다. 프로젝트와 상관없이 쌓입니다. 사용자가 다른 위치를 원하면 모든 명령에 `--lib <폴더>`를 붙이거나 `WEBD_LIBRARY` 환경 변수를 씁니다. 위치를 바꾸면 그 사실을 알립니다.

```
<라이브러리>/
  index.html            목록 페이지 (저장·삭제 때마다 다시 만듦)
  <id>/component.html   단독으로 열리는 컴포넌트
  <id>/meta.json        이름, 분류, 태그, 저장·수정 시각, 출처, 미리보기 크기, 원래 배경색(background)
  <id>/history/         덮어쓰기 전 버전
  <id>/.draft.json      편집 화면에서 저장하지 않은 변경 (편집 중일 때만)
  .trash/               삭제한 항목
```

## WebD 새 작업에서 조각 검토

1. 한 조각을 단독 HTML로 만든 뒤 WebD의 자동 검사와 비평으로 명백한 결함을 고칩니다.
2. 아래 저장 명령으로 조각을 저장합니다. 저장은 검토를 위한 스냅샷입니다.
3. `library.mjs edit <id> --no-open`을 실행하고 편집기 주소를 내부 브라우저에서 엽니다. 사용자와 함께 화면을 보며 조정합니다. 사용자에게서 말로 받은 수정은 먼저 `.draft.json`을 확인하고 `save --id <id> --file <수정 HTML>`로 반영합니다.
4. 사용자가 확인한 버전과 ID를 기록한 뒤 다음 조각으로 넘어갑니다. 사용자가 없으면 **사용자 검토 대기**로 남깁니다. 화면에는 확정된 조각만 조립하고 화면 자체도 별도로 검토받습니다.

## 저장하기

사용자가 "이 부분 저장해 줘"라고 하면:

1. **대상 확인**: 어느 파일의 어느 부분인지 정합니다. 애매하면 후보(섹션 이름, 선택자)를 보여 주고 고르게 합니다.
2. **단독 HTML로 뽑기**: 임시 폴더에 HTML 파일 하나를 만듭니다. 이 파일을 복사해 새 화면에 넣었을 때 요청한 조각만 보여야 합니다.
   - 해당 마크업과 그 마크업에 실제로 쓰이는 CSS만 넣습니다. 쓰지 않는 규칙은 뺍니다.
   - 참조하는 CSS 변수(토큰)는 `:root`에 값과 함께 넣습니다. 바깥 파일에 기대지 않습니다.
   - 웹폰트를 쓰면 `<link>`도 넣습니다. 이미지는 원격 URL이면 그대로 두고, 로컬 파일이면 사용자에게 알리고 자리 표시로 바꿉니다.
   - 클래스 이름이 다른 컴포넌트와 부딪히지 않게 컴포넌트 이름으로 시작하게 바꾸는 것을 검토합니다(예: `.roast-curve__line`).
   - 스크립트가 필요한 컴포넌트는 그 스크립트도 같은 파일에 넣습니다.
   - 실제 서비스 데이터·개인정보·비밀값이 들어 있으면 저장 전에 자리 표시로 바꾸고 알립니다.
3. **검사**: 등록 후보를 단독으로 열어 요청한 조각이 화면에 실제로 몇 개 보이는지 확인합니다. 버튼은 하나만 보이는 상태에서 해당되는 마우스·키보드·터치 입력을 직접 넣어 상태가 바뀌는지 확인합니다. 렌더 후 스크립트가 만든 상태 견본도 확인 대상입니다. WebD 검출기를 돌리고 high가 있으면 저장 전에 알립니다(사용자가 그대로 저장하라면 따름).
   ```
   node "<webd 스킬 폴더>/scripts/detect.mjs" <임시 HTML>
   ```
   webd 스킬 폴더는 이 스킬 폴더와 같은 위치의 `webd`입니다(`<스킬 폴더>/../webd`).
4. **저장**:
   ```
   node "<스킬 폴더>/scripts/library.mjs" save --file <임시 HTML> --name "<이름>" \
     --category <분류> --tags <태그,태그> --desc "<한 줄 설명>" \
     --project "<프로젝트 이름>" --source "<원본 파일 경로>" --style "<DESIGN.md 근거 한 줄>" --viewport <너비>x<높이>
   ```
   - 입력 파일은 UTF-8 `.html` 또는 `.htm`입니다.
   - 분류: `hero nav button form table chart card list section footer feedback other`
   - `button`은 정적 HTML에서 조작 컨트롤 하나만 허용합니다. 비교 화면을 넘기면 CLI와 편집기 저장이 파일·버전·목록을 쓰기 전에 거절합니다. 정적 통과와 브라우저 동작 확인을 따로 기록합니다.
   - 이름·설명은 사용자 말투 그대로, 짧게. 태그는 3개 이하.
   - `--viewport`는 이 컴포넌트가 제대로 보이는 크기입니다. 버튼처럼 작은 것은 `600x240`, 섹션은 `1200x720` 정도.
   - 시각(`createdAt`, `updatedAt`)은 스크립트가 로컬 시간대로 기록합니다. 직접 쓰지 않습니다.
5. **등록 확인·보고**: 목록에서 해당 항목을 다시 조회하고 저장된 HTML 또는 편집기 미리보기가 검사한 조각과 일치하는지 확인합니다. 저장한 ID, 버전, 파일 경로와 목록 페이지 경로를 알립니다.

## 고쳐서 다시 저장

같은 컴포넌트를 고친 버전이면 `--id <기존 id>`로 저장합니다. 이전 파일은 `history/`로 옮겨지고 `createdAt`은 유지, `updatedAt`과 `versions`만 바뀝니다. 이름·분류 등은 넘긴 옵션만 바뀝니다.

## 목록 보기

사용자가 목록을 보고 싶어 하면 `list`로 현재 등록 항목을 읽고 기존 `index.html`을 보여 줍니다. 목록 파일을 다시 만들어야 할 때는 `index`를 사용합니다.

```
node "<스킬 폴더>/scripts/library.mjs" index
```

목록 페이지에서 할 수 있는 것:
- 미리보기는 각 컴포넌트의 외형을 확인하는 썸네일입니다. 포인터 입력은 받지 않습니다. 조작을 확인하려면 카드의 **열기**를 누르거나 편집기의 미리보기를 사용합니다. **편집**은 편집 명령을 복사합니다. HTML·ID도 복사할 수 있습니다.
- **미리보기 배경 원래/중립**: 기본은 원래 배경. 중립은 라이트 연회색·다크 어두운 회색 단색이고, 카드에 원래 배경색 칩이 붙음. 저장된 `component.html`은 바뀌지 않음
- 검색(이름·설명·태그), 분류·태그 필터, **기간 필터**(정렬 기준 날짜로 거름)
- **정렬**: 저장일·수정일(최신/오래된), 이름, 분류. 날짜 정렬은 월별, 분류 정렬은 분류별로 묶어 보여 줌
- 고른 필터·정렬은 그 브라우저에만 기억됨

터미널에서 바로 답할 때는 `list`를 씁니다.

```
node "<스킬 폴더>/scripts/library.mjs" list --sort updated --since 2026-10-01 --until 2026-10-31 --category button
```

옵션: `--sort created|updated|name|category`, `--order asc|desc`, `--since`·`--until YYYY-MM-DD`, `--category`, `--tag`, `--q`, `--json`. 기간은 정렬 기준 날짜(수정일 정렬이면 수정일, 그 밖에는 저장일)로 거릅니다.

## CSS 편집

사용자가 "편집기로 열어 줘", "간격 직접 만져 볼게"처럼 화면에서 직접 고치려 하면 편집 서버를 띄웁니다. 사용자는 CSS를 직접 고치거나 말로 피드백을 줄 수 있습니다.

```
node "<스킬 폴더>/scripts/library.mjs" edit <id> [--port <번호>] [--no-open]
```

1. Codex에서는 `--no-open`으로 실행하고 출력된 로컬 주소를 내부 브라우저에 엽니다. 브라우저가 없으면 사용자가 쓸 수 있는 로컬 브라우저로 확인합니다. 주소의 편집 토큰은 해당 세션에서만 사용하고 보고나 로그에 옮기지 않습니다.
2. 화면에서 할 수 있는 것을 짧게 알립니다: 왼쪽 HTML 요소 트리에서 선택·접기·펼치기(또는 "요소 선택"을 켜고 미리보기에서 클릭) → 오른쪽에서 걸린 규칙의 속성·값 직접 수정(↑↓로 숫자 조절), 체크박스로 끄기, 속성 추가, CSS 전체 탭에서 원문 수정, 박스 모델 색 표시와 "전체 간격 보기", 저장(Ctrl+S)·되돌리기.
3. 값이 토큰(`var(--x)`)이면: 그 자리를 숫자로 바꾸면 그 규칙만, "이 요소가 쓰는 토큰"에서 바꾸면 그 토큰을 쓰는 곳이 모두 바뀝니다. 사용자가 어느 쪽인지 물으면 이 차이를 설명합니다.
4. 사용자가 말로 피드백을 주면("패딩 좀 줄여"): `component.html`의 수정본을 별도 파일로 만든 뒤 `save --id <id> --file <수정 HTML>`로 저장합니다. 편집 화면이 파일 변경을 알아채고 다시 불러옵니다. 화면에 저장 안 한 변경이 있으면 편집 화면이 사용자에게 묻습니다. 고치기 전에 `<id>/.draft.json`이 있으면 읽어서, 화면에서 바꾸던 내용과 부딪히지 않는지 먼저 확인합니다.
5. "화면에서 바꾸던 거 정리해 줘"라고 하면 `.draft.json`의 `log`(무엇을 어디서 바꿨는지)와 `styles`(지금 화면의 `<style>` 원문)를 읽어 설명하거나 이어서 정리합니다. 저장은 사용자가 화면에서 하거나, 사용자가 요청하면 `styles`를 반영한 파일로 `save --id`를 실행합니다.
6. 다 끝나면 편집 서버를 끕니다(백그라운드 작업 중지). 저장한 버전과 history 경로를 보고합니다.

화면에서 고치지 않는 것: `style` 속성(인라인), 바깥 CSS 파일. 스크립트가 `<style>`을 더하거나 바꾸는 컴포넌트는 편집이 막히니 말로 요청받아 고칩니다.

## 다시 쓰기

"저장한 ○○ 가져와"라고 하면:

1. `list --q <검색어>` 또는 `show <id>`로 찾습니다. 후보가 여럿이면 보여 주고 고르게 합니다.
2. `component.html`을 읽습니다.
3. 지금 프로젝트에 맞게 옮깁니다.
   - 지금 프로젝트에 `DESIGN.md`가 있으면 **토큰을 그 값으로 바꿉니다.** 저장된 색·폰트를 그대로 가져오면 화면이 따로 놉니다. 원래 모습 그대로 쓰라고 하면 그대로 둡니다.
   - 프로젝트 스택에 맞게 바꿉니다(HTML → JSX의 `className`, 컴포넌트 파일 분리 등).
   - 기존 클래스·변수와 이름이 겹치는지 확인합니다.
4. 무엇을 바꿔서 옮겼는지 보고합니다.

## 삭제

`remove <id>`는 바로 지우지 않고 `.trash/`로 옮깁니다. 실행 전에 이름과 id를 보여 주고 확인을 받습니다. 휴지통을 비우는 것은 사용자가 따로 요청할 때만, 무엇이 지워지는지 다시 확인한 뒤에 합니다.
