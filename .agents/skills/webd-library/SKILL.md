# WebD 라이브러리

UI 컴포넌트를 단독으로 열리는 HTML로 저장하고, 목록 페이지에서 미리보기·검색·기간 필터·정렬로 찾아 다른 곳에서 다시 씁니다.

## 등록 단위

- **사용자가 가리킨 컴포넌트 하나를 따로 가져다 쓸 수 있게 저장합니다.** 제목, 설명, 조작 안내, 상태 견본, 전체 화면과 조합 예제는 검토 화면에서만 보여 줍니다. 목록·보기 요청은 읽기 작업으로 처리합니다.
- **버튼 한 개를 저장할 때는 실제 조작 컨트롤 한 개만 넣습니다.** 버튼 모양 링크는 `href`가 있는 링크 한 개를 씁니다. 같은 버튼의 기본·호버·눌림·선택은 한 컨트롤의 CSS 또는 동작으로 재현합니다. 버튼 복제본과 상태표를 여러 개 두지 않습니다. 아이콘은 그 버튼 자체의 일부일 때만 내부에 둡니다.
- **버튼 상태에 크기 변화(`scale()`·`zoom`·크기 전환)를 넣지 않습니다.** 호버·눌림·선택은 색·테두리·빛·위치로 표현합니다. 크기 연출은 엔진에서 붙입니다.
- 메뉴·표·폼처럼 여러 요소가 함께 한 역할을 하는 경우에는 그 컴포넌트의 경계를 정하고 해당 분류로 저장합니다. 버튼 검사를 피하려고 분류를 바꾸지 않습니다.
- 스프라이트 시트·PNG·좌표 JSON·캡처는 별도 산출 경로에 둡니다. 같은 에셋의 상태를 한 시트에 묶을 수 있으며, 서로 다른 에셋은 별도로 내보냅니다. 에셋 산출 요청만으로 라이브러리에 등록하지 않습니다.

`<스킬 폴더>`는 현재 읽는 `SKILL.md`가 들어 있는 폴더입니다. 스크립트는 의존성 없는 Node 18+ 스크립트입니다.

```
node "<스킬 폴더>/scripts/library.mjs" <명령> [옵션]
```

## 저장 위치

기본은 사용자 홈의 `~/.webd/library/`입니다. 프로젝트와 상관없이 쌓입니다. 사용자가 다른 위치를 원하면 모든 명령에 `--lib <폴더>`를 붙이거나 `WEBD_LIBRARY` 환경 변수를 씁니다. 위치를 바꾸면 그 사실을 알립니다.

```
<라이브러리>/
  index.html            목록 페이지 (저장·삭제 때마다 다시 만듦)
  <id>/component.html   단독으로 열리는 컴포넌트
  <id>/meta.json        이름, 종류(kind), 가상 폴더(folder), 분류, 태그, 저장·수정 시각, 출처, 미리보기 크기, 원래 배경색(background)
  <id>/history/         덮어쓰기 전 버전
  <id>/.draft.json      편집 화면에서 저장하지 않은 변경 (편집 중일 때만)
  <id>/export.json      내보내기 설정과 마지막 내보내기 기록
  .folders.json         사용자가 만든 가상 폴더 목록(빈 폴더 포함)
  .trash/               삭제한 항목
```

### 가상 폴더와 프리셋 종류

라이브러리는 **프리셋 저장소**입니다. 정리는 사용자가 만드는 **가상 폴더**로 하고(하위 폴더 가능, 예: `잿빛 등대/대사창`), 종류는 무엇을 저장했는지만 나타냅니다.

- 폴더는 `meta.json`의 `folder`에 경로로만 적습니다. 실제 `<id>/` 폴더는 옮기지 않으므로 편집기 주소, 묶음 시트 구성원, 내보내기 경로(`export/<id>/`)는 폴더를 바꿔도 그대로입니다. 옮기기·이름 바꾸기는 `updatedAt`·`versions`를 바꾸지 않습니다.
- 폴더를 지우면 안의 프리셋과 하위 폴더는 한 단계 위로 올라갑니다. 프리셋은 지우지 않습니다.
- 종류(`--kind`): `component`(컴포넌트) `screen`(화면·조립) `pattern`(무늬·아이콘) `token`(색·글꼴·간격 토큰) `effect`(효과·애니메이션). 예전 항목은 `kind`가 없으면 분류·태그로 추정해 보여 줍니다(meta는 고치지 않음).
- 사용자가 정하지 않은 폴더 구조를 에이전트가 임의로 만들지 않습니다. 저장할 때 폴더를 모르면 묻거나 폴더 없이 저장합니다.

내보낸 PNG·JSON은 라이브러리 밖 `<라이브러리 실제 경로의 상위>/export/<id>/`에 씁니다(`WEBD_EXPORT`로 상위 폴더 변경, 컴포넌트마다 편집기에서 직접 지정 가능). 컴포넌트를 지워도 산출물은 남습니다.

## WebD 새 작업에서 컴포넌트 검토

1. 컴포넌트 하나를 단독 HTML로 만든 뒤 WebD의 자동 검사와 비평으로 명백한 결함을 고칩니다.
2. 아래 저장 명령으로 컴포넌트를 저장합니다. 저장은 검토를 위한 스냅샷입니다.
3. `library.mjs edit <id> --no-open`을 백그라운드로 실행하고 출력된 편집기 주소를 내부 브라우저에서 엽니다. 사용자와 함께 화면을 보며 조정합니다. 사용자에게서 말로 받은 수정은 먼저 `.draft.json`을 확인하고 `save --id <id> --file <수정 HTML>`로 반영합니다.
4. 사용자가 확인한 버전과 ID를 기록한 뒤 다음 컴포넌트로 넘어갑니다. 사용자가 없으면 **사용자 검토 대기**로 남깁니다. 화면에는 확정된 컴포넌트만 조립하고 화면 자체도 별도로 검토받습니다.

## 저장하기

사용자가 "이 부분 저장해 줘"라고 하면:

1. **대상 확인**: 어느 파일의 어느 부분인지 정합니다. 애매하면 후보(섹션 이름, 선택자)를 보여 주고 고르게 합니다.
2. **단독 HTML로 뽑기**: 임시 폴더에 HTML 파일 하나를 만듭니다. 이 파일을 복사해 새 화면에 넣었을 때 요청한 컴포넌트만 보여야 합니다.
   - 해당 마크업과 그 마크업에 실제로 쓰이는 CSS만 넣습니다. 쓰지 않는 규칙은 뺍니다.
   - 참조하는 CSS 변수(토큰)는 `:root`에 값과 함께 넣습니다. 바깥 파일에 기대지 않습니다.
   - 웹폰트를 쓰면 `<link>`도 넣습니다. 이미지는 원격 URL이면 그대로 두고, 로컬 파일이면 사용자에게 알리고 자리 표시로 바꿉니다.
   - 클래스 이름이 다른 컴포넌트와 부딪히지 않게 컴포넌트 이름으로 시작하게 바꾸는 것을 검토합니다(예: `.roast-curve__line`).
   - 스크립트가 필요한 컴포넌트는 그 스크립트도 같은 파일에 넣습니다.
   - 실제 서비스 데이터·개인정보·비밀값이 들어 있으면 저장 전에 자리 표시로 바꾸고 알립니다.
3. **검사**: 등록 후보를 단독으로 열어 요청한 컴포넌트가 화면에 실제로 몇 개 보이는지 확인합니다. 버튼은 하나만 보이는 상태에서 해당되는 마우스·키보드·터치 입력을 직접 넣어 상태가 바뀌는지 확인합니다. 렌더 후 스크립트가 만든 상태 견본도 확인 대상입니다. WebD 검출기를 돌리고 high가 있으면 저장 전에 알립니다(사용자가 그대로 저장하라면 따름).
   ```
   node "<webd 스킬 폴더>/scripts/detect.mjs" <임시 HTML>
   ```
   webd 스킬 폴더는 이 스킬 폴더와 같은 위치의 `webd`입니다(`<스킬 폴더>/../webd`).
4. **저장**:
   ```
   node "<스킬 폴더>/scripts/library.mjs" save --file <임시 HTML> --name "<이름>" \
     --kind <종류> --folder "<폴더 경로>" --category <분류> --tags <태그,태그> --desc "<한 줄 설명>" \
     --project "<프로젝트 이름>" --source "<원본 파일 경로>" --style "<DESIGN.md 근거 한 줄>" --viewport <너비>x<높이>
   ```
   - 입력 파일은 UTF-8 `.html` 또는 `.htm`입니다.
   - 종류: `component screen pattern token effect`. 폴더: 사용자가 정한 가상 폴더 경로(`--folder ""`는 폴더 없음, 생략하면 다시 저장할 때 기존 폴더 유지).
   - 분류(예전 방식, 버튼 검사에 씀): `hero nav button form table chart card list section footer feedback other`
   - `button`은 정적 HTML에서 조작 컨트롤(버튼·`href` 있는 링크·버튼형 input·`role="button"`)이 정확히 하나일 때만 저장합니다. 그 옆의 글자·배지·장식 요소는 허용합니다. 컨트롤이 둘 이상(비교 화면)이거나, 입력칸이 섞였거나, 하나뿐인 컨트롤이 숨겨져 있으면 CLI와 편집기 저장이 파일·버전·목록을 쓰기 전에 거절합니다. 정적 통과와 브라우저 동작 확인을 따로 기록합니다.
   - 이름·설명은 사용자 말투 그대로, 짧게. 태그는 3개 이하.
   - `--viewport`는 이 컴포넌트가 제대로 보이는 크기입니다. 버튼처럼 작은 것은 `600x240`, 섹션은 `1200x720` 정도.
   - 시각(`createdAt`, `updatedAt`)은 스크립트가 로컬 시간대로 기록합니다. 직접 쓰지 않습니다.
5. **등록 확인·보고**: 목록에서 해당 항목을 다시 조회하고 저장된 HTML 또는 편집기 미리보기가 검사한 컴포넌트와 일치하는지 확인합니다. 저장한 ID, 버전, 파일 경로와 목록 페이지 경로를 알립니다.

## 고쳐서 다시 저장

같은 컴포넌트를 고친 버전이면 `--id <기존 id>`로 저장합니다. 이전 파일은 `history/`로 옮겨지고 `createdAt`은 유지, `updatedAt`과 `versions`만 바뀝니다. 이름·분류 등은 넘긴 옵션만 바뀝니다.

## 목록 보기

사용자가 목록을 보고 싶어 하면 **라이브러리 서버**로 엽니다. 카드(미리보기·이름)를 누르면 그 컴포넌트의 편집기가 같은 탭에서 열리고, 편집기 왼쪽 위 `← 라이브러리`로 돌아옵니다.

```
node "<스킬 폴더>/scripts/library.mjs" open [--port <번호>] [--no-open] [--no-watch] [--lan]
```

같은 일을 하는 바로가기: 저장소 루트의 `webd-library.cmd`(Windows, 더블클릭 또는 `webd-library.cmd --lan`처럼 인자 전달), Claude Code 플러그인 명령 `/jbro-webd:library [인자]`(서버를 백그라운드로 띄우고 사용자 브라우저를 직접 엶 — 접속 토큰은 대화에 옮기지 않음). 라이브러리 폴더는 `--lib`, 없으면 환경변수 `WEBD_LIBRARY`.

Codex에서는 `--no-open`으로 백그라운드 실행하고 출력된 주소를 내부 브라우저에 엽니다. 주소의 토큰은 처음 한 번만 쓰이고(이후 같은 서버는 HttpOnly 쿠키로 확인), 보고나 로그에 옮기지 않습니다. 다 쓰면 서버를 끕니다.

- 스킬 코드(`scripts/`·`editor/`, webd의 `render-check.mjs`)가 바뀌면 서버가 **같은 포트·토큰으로 저절로 다시 뜹니다**. 열린 탭은 새로 고침만 하면 됩니다. 끄려면 `--no-watch`.
- `--lan`: 같은 와이파이의 폰·태블릿에서 열 수 있게 이 PC의 사설 IP(192.168.x 등)로도 엽니다. 터미널에 "같은 와이파이" 주소가 따로 나옵니다. 토큰을 아는 사람만 들어오고, PC 밖에서 온 요청은 컴포넌트 파일도 토큰이 있어야 받습니다. 공용 와이파이에서는 쓰지 않고, 처음 열 때 Windows 방화벽 허용 창이 뜰 수 있습니다(사용자가 정함). 사용자가 요청할 때만 켭니다.

서버 없이 파일만 볼 때는 `index.html`(저장·삭제 때마다 다시 만듦, 필요하면 `index`)을 엽니다. 이때는 바로 편집할 수 없어서 맨 위에 `open` 명령 복사 안내가 뜨고, 카드의 **편집 명령 복사**로 편집기를 엽니다.

목록 페이지에서 할 수 있는 것:
- 위쪽 **메뉴 바**(편집기와 같은 모양, F10·Alt로 이동): **파일**(새 폴더·이름 바꾸기·지우기·폴더 제안 적용·라이브러리 경로 복사), **편집**(이 폴더 모두 선택 Ctrl+A·선택 해제 Esc·선택 항목 폴더로 옮기기·HTML·ID 복사·휴지통으로 Delete), **보기**(미리보기 배경·정렬·종류·필터 초기화·폴더 펼치기/접기), **내보내기**(선택 항목을 각자 설정대로 내보내기·묶음 시트 만들기·저장한 묶음 시트), **도움말**(단축키).
- 왼쪽 **폴더 트리**: 모든 프리셋 / 사용자 폴더(하위 포함 수) / 폴더 없음. 서버로 열었을 때는 새 폴더·이름 바꾸기·지우기·**폴더를 묶음 시트로** 아이콘이 있고, 카드를 폴더로 **끌어** 옮기거나 카드의 **폴더로 옮기기** 메뉴를 씁니다. 폴더 없는 프리셋 중 이름이 태그로 시작하는 것이 있으면 **폴더 제안** 버튼이 뜹니다(누를 때만 옮김).
- 카드 왼쪽 위 **선택**: 하나의 선택으로 옮기기·내보내기·묶음 시트·휴지통을 모두 합니다(예전 '묶음' 칩은 선택으로 합침). 휴지통은 `.trash/`로 옮길 뿐 바로 지우지 않습니다.
- 미리보기는 각 프리셋의 외형을 확인하는 썸네일입니다. 포인터 입력은 받지 않습니다. 카드 버튼: **편집**(편집기), **내보내기**(편집기의 내보내기 탭), 폴더로 옮기기, HTML·ID 복사, **원본**(새 탭에서 열기). 설명은 모두 툴팁에 있습니다.
- **미리보기 배경 원래/중립**(보기 메뉴): 기본은 원래 배경. 중립은 라이트 연회색·다크 어두운 회색 단색이고, 카드에 원래 배경색 칩이 붙음. 저장된 `component.html`은 바뀌지 않음
- 검색(이름·설명·태그), 종류·태그 필터, **기간 필터**(정렬 기준 날짜로 거름)
- **정렬**: 저장일·수정일(최신/오래된), 이름, 종류. 날짜 정렬은 월별, 종류 정렬은 종류별로 묶어 보여 줌
- 고른 폴더·필터·정렬은 그 브라우저에만 기억됨

터미널에서 바로 답할 때는 `list`를 씁니다.

```
node "<스킬 폴더>/scripts/library.mjs" list --sort updated --since 2026-10-01 --until 2026-10-31 --category button
```

옵션: `--sort created|updated|name|category`, `--order asc|desc`, `--since`·`--until YYYY-MM-DD`, `--folder <폴더>`(하위 포함, `""`는 폴더 없음), `--kind`, `--category`, `--tag`, `--q`, `--json`. 기간은 정렬 기준 날짜(수정일 정렬이면 수정일, 그 밖에는 저장일)로 거릅니다.

폴더 명령: `move <id> [<id>…] --folder <폴더>`, `folder list`, `folder add <폴더>`, `folder rename <폴더> <새 경로>`, `folder remove <폴더>`, `folder suggest [--apply]`(이름이 태그로 시작하는 프리셋을 그 태그 폴더로, `--apply` 없이는 보여 주기만). 사용자의 폴더 구조를 바꾸는 명령은 사용자가 요청했을 때만 씁니다.

## CSS 편집

사용자가 "편집기로 열어 줘", "간격 직접 만져 볼게"처럼 화면에서 직접 고치려 하면 편집 서버를 띄웁니다. 사용자는 CSS를 직접 고치거나 말로 피드백을 줄 수 있습니다.

```
node "<스킬 폴더>/scripts/library.mjs" edit <id> [--port <번호>] [--no-open]
```

`edit`는 `open`과 같은 라이브러리 서버를 띄우고 그 컴포넌트의 편집기를 바로 엽니다. 이미 `open`으로 띄운 서버가 있으면 목록에서 카드를 누르면 됩니다.

1. Codex에서는 `--no-open`으로 실행하고 출력된 로컬 주소를 내부 브라우저에 엽니다. 브라우저가 없으면 사용자가 쓸 수 있는 로컬 브라우저로 확인합니다. 주소의 편집 토큰은 해당 세션에서만 사용하고 보고나 로그에 옮기지 않습니다.
2. 화면에서 할 수 있는 것을 짧게 알립니다: 왼쪽 HTML 요소 트리에서 선택·접기·펼치기(또는 가운데 캔버스에서 왼쪽 클릭. 캔버스는 오른쪽 끌기·휠로 이동, Ctrl+휠로 확대, 그냥 오른쪽 클릭은 메뉴) → 오른쪽에서 걸린 규칙의 속성·값 직접 수정(↑↓로 숫자 조절), 체크박스로 끄기, 속성 추가, CSS 전체 탭에서 원문 수정, 박스 모델 색 표시와 "전체 간격 보기", 저장(Ctrl+S)·되돌리기.
   계층 구조 편집(유니티처럼): 오른쪽 클릭·`+` 메뉴와 단축키로 잘라내기·복사·붙여넣기(`Ctrl+V` 형제, `Ctrl+Shift+V` 자식)·복제(`Ctrl+D`)·삭제·이름(클래스) 바꾸기(`F2`)·빈 부모 만들기(`Ctrl+Shift+G`)·맨 앞/뒤로·빈 자식(`Alt+Shift+N`)·텍스트·버튼 만들기, 스타일 탭 "글자"로 내용 수정. 복사는 걸린 CSS를 함께 담아 다른 컴포넌트에 붙여도 모양이 같고, 시스템 클립보드에도 `<style>` + HTML로 들어갑니다.
3. 값이 토큰(`var(--x)`)이면: 그 자리를 숫자로 바꾸면 그 규칙만, "이 요소가 쓰는 토큰"에서 바꾸면 그 토큰을 쓰는 곳이 모두 바뀝니다. 사용자가 어느 쪽인지 물으면 이 차이를 설명합니다.
4. 사용자가 말로 피드백을 주면("패딩 좀 줄여"): `component.html`의 수정본을 별도 파일로 만든 뒤 `save --id <id> --file <수정 HTML>`로 저장합니다. 편집 화면이 파일 변경을 알아채고 다시 불러옵니다. 화면에 저장 안 한 변경이 있으면 편집 화면이 사용자에게 묻습니다. 고치기 전에 `<id>/.draft.json`이 있으면 읽어서, 화면에서 바꾸던 내용과 부딪히지 않는지 먼저 확인합니다.
5. "화면에서 바꾸던 거 정리해 줘"라고 하면 `.draft.json`의 `log`(무엇을 어디서 바꿨는지)와 `styles`(지금 화면의 `<style>` 원문), 구조를 바꿨으면 `body`(지금 화면의 `<body>` 안쪽)를 읽어 설명하거나 이어서 정리합니다. 저장은 사용자가 화면에서 하거나, 사용자가 요청하면 `styles`·`body`를 반영한 파일로 `save --id`를 실행합니다.
6. 다 끝나면 편집 서버를 끕니다(백그라운드 작업 중지). 저장한 버전과 history 경로를 보고합니다.

편집기 위쪽 **메뉴 바**: **파일**(저장·복제해서 새 프리셋으로·이전 버전으로 되돌리기·폴더로 옮기기·원본 열기·라이브러리로), **편집**(되돌리기·요소 잘라내기/복사/붙여넣기/복제/삭제·요소 만들기·빈 부모·이름 바꾸기·**요소 이름 복사**·**요소 CSS 복사**), **보기**(요소 선택 V·전체 간격·미리보기 폭·탭), **상태**(상태 걸기·재생/멈춤·프레임 이동·fps), **내보내기**(지금 설정으로 내보내기 Ctrl+E·배율·내보낸 폴더 열기·묶음 시트에 넣기), **도움말**(단축키). 이전 버전으로 되돌리면 그 내용을 새 버전으로 저장하고 지금 파일은 history에 남습니다. 복제는 화면 내용(저장 안 한 변경 포함)으로 새 프리셋을 만들고 폴더·종류·태그·내보내기 설정을 따라갑니다.

화면에서 고치지 않는 것: `style` 속성(인라인)과 그 밖의 HTML 속성, 바깥 CSS 파일, 끌어서 옮기기(계층 드래그). 스크립트가 `<style>`을 더하거나 바꾸는 컴포넌트는 편집이 막히고, 스크립트가 본문 요소를 바꾸는 컴포넌트는 구조 편집이 막히니(복사는 됨) 말로 요청받아 고칩니다.

## 스프라이트 내보내기

설계·근거: 저장소 `docs/EXPORT-DESIGN.md`. 지금 되는 것은 1·2·3단계(한 장·9-slice·3-slice, 배율, PNG + JSON, 상태별 시트, CSS 애니메이션 프레임)입니다. JS로 움직이는 애니메이션, 상태 전환 프레임, 엔진 가져오기 파일은 아직이라 요청받으면 먼저 알립니다.

편집기 오른쪽 **내보내기** 탭에서 합니다(목록 카드의 **내보내기**로 바로 열 수도 있음). 설치된 Chrome·Edge를 헤드리스로 띄워 렌더합니다(없으면 `WEBD_BROWSER`로 경로 지정).

- **대상**: 컴포넌트 전체 또는 계층에서 고른 요소. 고른 요소면 계층에서 다른 요소를 고르는 대로 대상이 따라 바뀝니다. 9·3-slice는 틀을 그리는 요소(예: `clip-path`로 깎은 판)를 대상으로 고르는 것이 정확합니다.
- 패널 순서: **종류**(자르기·애니메이션) → **캡처**(대상·배경·범위·상태) → **출력**. 선택지는 아이콘 + 짧은 이름이고, 설명은 전부 툴팁으로만 나옵니다(이름의 점선 밑줄·버튼에 마우스를 올리거나 키보드로 포커스). 배율은 하나만 고릅니다(예전 설정에 여러 개가 있으면 열 때 가장 작은 것으로 줄임).
- **배경** 투명/원래 배경, **범위** 그려진 픽셀(그림자·광채 포함, 빈 여백 트림)/상자 그대로.
- **9-slice·3-slice**: 인셋 L·T·R·B(CSS px). `추정`은 테두리 두께·`border-radius`·`clip-path: polygon()` 모서리 깎임으로 정하고 근거를 보여 줍니다. 미리보기의 점선을 끌어 바꿀 수 있습니다. 가운데 늘림/반복, 크기 최소(인셋 + 가운데 4px로 다시 렌더)/원래, 틀만 찍기(글자·아이콘만 숨김. 판·모서리처럼 글자 없는 장식 요소는 대상의 자식이어도 남고, 글자만 품은 상자는 상자째 숨김).
- **상태**: CSS에 상태 규칙이 있으면 자동으로 찾아 상태마다 다시 렌더합니다(가상 클래스 `:hover`·`:active`·`:focus-visible`·`:disabled` 등, 속성 `[aria-pressed="true"]`·`[data-*="…"]`, 문서에 없는 클래스 `.is-*`·BEM `--변형`, CSS에 있는 조합). 내보내기 탭 "상태" 줄에서 켜고 끄며, 기본과 똑같이 보이는 상태는 내보낼 때 뺍니다. 상태가 여럿이면 `<이름>-sheet.png` 한 장과 JSON(`meta.frameTags`·`meta.webd.states`에 상태 이름)으로, 또는 상태마다 파일로 씁니다. 상태 규칙이 없는 컴포넌트는 기본 한 장입니다(게임이 상태를 바꾸는 컴포넌트는 아직 직접 추가 불가).
- **애니메이션**: CSS 애니메이션(`@keyframes`)이 있으면 상태마다 길이를 재서 fps 간격 프레임으로 찍습니다(내보내기 탭 "애니메이션"에서 켜고 끄고 fps 8·12·24·30·60). 주기가 다른 반복은 최소공배수 길이로, 모든 프레임은 같은 크기로. JSON 프레임 이름은 `이름_상태_번호`, `duration`·상태별 `frameTags`·`meta.webd.animation`. 상태·컴포넌트는 브라우저 창 4개(`WEBD_CAPTURE_TABS`로 1–8)에서 동시에 찍습니다. 프레임이 많으면 미리보기가 몇 초 걸립니다(점등 신호 버튼 24fps 상태 5개 약 3.5초).
- **타임라인**: 미리보기 위 "상태" 줄에서 칸을 고르면 그 상태를 미리보기에 겁니다(고른 요소에만, 저장 안 됨). 그 아래 "프레임" 줄에서 재생·멈춤, 칸을 누르거나 끌어서(스크럽) 그 시각에 멈춤, fps 고르기. 사용자에게 상태·프레임을 보여 줄 때 씁니다.
- **결과**: 설정을 바꾸면 실제로 렌더한 PNG가 나오고(작으면 정수배 확대 표시), 9·3-slice는 모서리를 끌어 늘려 보는 칸이 함께 나옵니다. 최소 크기에서 장식이 사라지는 등 문제는 경고로 보여 주고 JSON에도 남깁니다.
- **출력**: `<이름>.png`·`<이름>@2x.png`마다 같은 이름의 `.json`. JSON은 Aseprite 호환(`frames`, `meta.slices[].keys[].center`)이고 `meta.webd.engines`에 Unity(`border` L·B·R·T, Sliced/Tiled), Godot(`patch_margin_*`, `axis_stretch_*`), CSS `border-image` 값이 들어 있습니다. 같은 이름의 이전 파일은 `.previous/`로 옮깁니다.
- 저장하지 않은 CSS 변경도 화면 그대로 내보냅니다(패널에 표시). 설정은 `<id>/export.json`에 남아 다음에 그대로 다시 내보낼 수 있습니다.
- 에이전트가 대신 내보낼 때는 편집기를 열어 사용자와 같이 결과·늘려 보기를 확인한 뒤 내보내기를 누르고, 쓴 폴더와 파일 이름, 경고를 보고합니다.
- **묶음 시트**: 목록의 **내보내기 > 묶음 시트 만들기**(고른 카드, 없으면 고른 폴더)나 폴더 트리의 **폴더를 묶음 시트로**로 오른쪽 **서랍**을 엽니다. 서랍을 연 채로 카드를 더 고르고 **선택 추가**를 누르거나 목록에서 빼고, 이름·최대 크기(기본 2048)·2의 거듭제곱·투명 여백 다듬기를 정해 저장·미리보기·내보내기 합니다. 저장한 시트는 **내보내기 > 저장한 묶음 시트**에서, 편집기에서는 **내보내기 > 묶음 시트에 넣기**로 더합니다. 각 컴포넌트는 자기 `export.json` 그대로 찍히므로, 묶기 전에 컴포넌트마다 내보내기 설정(대상·9-slice·상태)이 맞는지 확인합니다. 배치는 MaxRects, 9·3-slice는 다듬지 않습니다. 정의는 `<라이브러리>/.atlases/<이름>.json`, 출력은 `<내보내기 루트>/atlases/<이름>/`. 명령줄: `node "<스킬 폴더>/scripts/library.mjs" atlas <이름> [--members id,id] [--max 2048] [--pot] [--no-trim] [--scales 1,2]`, 목록 `atlas --list`.

## 다시 쓰기

"저장한 ○○ 가져와"라고 하면:

1. `list --q <검색어>` 또는 `show <id>`로 찾습니다. 후보가 여럿이면 보여 주고 고르게 합니다.
2. `component.html`을 읽습니다.
3. 지금 프로젝트에 맞게 옮깁니다.
   - 지금 프로젝트에 `DESIGN.md`가 있으면 **토큰을 그 값으로 바꿉니다.** 저장된 색·폰트를 그대로 가져오면 화면이 따로 놉니다. 원래 모습 그대로 쓰라고 하면 그대로 둡니다.
   - 프로젝트 스택에 맞게 바꿉니다(HTML → JSX의 `className`, 컴포넌트 파일 분리 등).
   - 기존 클래스·변수와 이름이 겹치는지 확인합니다.
4. 무엇을 바꿔서 옮겼는지 보고합니다.
